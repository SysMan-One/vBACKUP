# VBACKUP -- сохранить файлы в saveset, восстановить, сравнить

VBACKUP хранит копии файлов в saveset-е. Saveset -- это один файл или
несколько файлов-томов. В нём лежат сами файлы, их владельцы, права,
времена, расширенные атрибуты и ACL. Ещё в нём есть контрольные суммы,
поэтому повреждение всегда обнаруживается, и запасные блоки, поэтому
небольшое повреждение исправляется.

VBACKUP работает как команда BACKUP в OpenVMS. Вы говорите, что читать
и куда писать:

```
VBACKUP входная-спецификация[,...] выходная-спецификация [/квалификаторы]
```

Что будет сделано, зависит от двух сторон:

```
файлы    ->  saveset       сохранение       vbackup /home/rrl rrl.bck
saveset  ->  каталог       восстановление   vbackup rrl.bck /tmp/back
saveset  /LIST             листинг          vbackup rrl.bck /LIST
saveset  /COMPARE          сравнение        vbackup rrl.bck /COMPARE
saveset  /EXTRACT=имя      один файл        vbackup rrl.bck /EXTRACT=rrl/a.txt
файлы    ->  каталог       копирование      vbackup /home/rrl /mnt/copy
saveset  /RECORD           в журнал         vbackup rrl.bck /RECORD
/JOURNAL /LIST             журнал           vbackup /JOURNAL /LIST
```

Saveset на входе VBACKUP узнаёт по содержимому, а не по имени. При
сохранении он понимает, что выход -- saveset, если имя кончается на
.bck, если дан /SAVE_SET или если имя "-" (стандартный вывод).

Шаблоны берите в кавычки -- VBACKUP раскрывает их сам:

```
$ vbackup '/home/rrl/.../*.c' sources.bck
```

Квалификатор можно сокращать, пока сокращение однозначно: /VER вместо
/VERIFY. Можно писать и по-юниксовому: --VERIFY. Слово, начинающееся с
косой черты, считается квалификатором, только если оно называет
квалификатор, поэтому /etc и /home -- это имена файлов. Одиночный
\`--\` заканчивает квалификаторы.

Код завершения: 0 -- всё хорошо, 1 -- были предупреждения (например,
файл менялся во время сохранения), 2 -- что-то не сделано (например,
файл не удалось прочитать).

## Параметры

### входная-спецификация

При сохранении: файлы и каталоги, через запятую. Каталог сохраняется
со всем содержимым. См. тему ШАБЛОНЫ.

При восстановлении, листинге, сравнении и извлечении: saveset. Дайте
имя первого тома, остальные тома VBACKUP найдёт сам.

При восстановлении можно дать несколько saveset-ов через запятую - они
восстанавливаются по очереди. С /INCREMENTAL сначала полный saveset,
затем инкрементальные в том порядке, в каком они делались.

При копировании: файлы и каталоги, как при сохранении.

### выходная-спецификация

При сохранении: создаваемый saveset. Если он уже есть, VBACKUP
остановится; /REPLACE -- перезаписать.

При восстановлении: каталог, куда восстанавливать. Создаётся при
необходимости.

При сравнении: каталог, с которым сравнивать. Без него файлы
сравниваются с теми местами, откуда были сохранены.

При извлечении: файл, куда писать. Без него или с "-" -- стандартный
вывод.

При копировании: каталог, куда копировать. Выход, который не saveset
(нет .bck, нет /SAVE_SET), означает копирование, как в BACKUP. Файлы
получают всё то же, что вернуло бы восстановление.

## /SAVE_SET -- выход это saveset

Говорит, что выходная спецификация -- saveset, как бы она ни
называлась. Не нужен, если имя кончается на .bck.

## /BLOCK_SIZE -- размер блока

```
/BLOCK_SIZE=n
```

Saveset состоит из блоков по n байт: от 8192 до 1048576, кратно 512.
По умолчанию 65536. Большие блоки чуть быстрее, маленькие -- меньше
теряется при порче одного блока.

## /GROUP_SIZE -- запасные блоки для починки

```
/GROUP_SIZE=n
```

После каждых n блоков данных VBACKUP пишет один XOR-блок. Если в
группе испортился один блок, при чтении он восстанавливается из
остальных: вы увидите %VBACKUP-I-BLKFIXED, и ничего не потеряно.

По умолчанию 10: saveset больше на 10%. n от 0 до 100; /GROUP_SIZE=0 --
XOR-блоков нет, чинить нечем.

## /VOLUME_SIZE -- нарезать saveset на тома

```
/VOLUME_SIZE=размер
```

Режет saveset на файлы такого размера. Нужно для диска с пределом
4 ГБ на файл (FAT32), для заливки в облако, для носителей
фиксированного размера. Размер может кончаться на K, M, G или T:

```
$ vbackup /home home.bck /VOLUME_SIZE=4G
```

Тома называются home.bck, home.bck.002, home.bck.003 и так далее.
Держите их вместе, в одном каталоге. Если том потерялся, файлы из
остальных томов всё равно восстанавливаются.

## /COMMENT -- заметка в saveset-е

```
/COMMENT="текст"
```

Сохраняет текст в saveset-е; /LIST его показывает.

## /PHYSICAL -- устройство целиком, поблочно

```
vbackup /dev/sdb1 /mnt/usb/sdb1.bck /PHYSICAL          сохранить устройство
vbackup /mnt/usb/sdb1.bck /dev/sdc1 /PHYSICAL /REPLACE восстановить на устройство
vbackup /mnt/usb/sdb1.bck /tmp/sdb1.img /PHYSICAL      восстановить в файл-образ
vbackup /mnt/usb/sdb1.bck /tmp/dir                     то же: dir/sdb1 -- образ
```

Копирует каждый блок устройства -- раздела или целого диска -- или
файла-образа: любая файловая система, зашифрованные тома, загрузочные
области. Блоки из нулей места в saveset-е не занимают. Работает и с
/DATA_FORMAT=COMPRESSED. Запускать от root.

Чем рискуем и что VBACKUP с этим делает:

- Устройство, на которое пишут во время копирования, даёт битую копию,
  и это не видно, пока она не понадобится. Устройство, смонтированное на
  запись (или с таким разделом), VBACKUP не берёт. Размонтируйте его,
  смонтируйте только на чтение или копируйте снимок (LVM, btrfs).
- Занятое устройство -- физический том LVM, член RAID, контейнер
  dm-crypt, swap -- тоже не берётся.
- Восстановление переписывает выходное устройство целиком. VBACKUP
  делает это только с /REPLACE, никогда на смонтированное или занятое
  устройство и никогда на меньшее, чем сохранённое. За терминалом надо
  набрать YES. Скрипт даёт /REPLACE, и его не спрашивают.
- На большее устройство копия ложится в начало; файловая система
  остаётся прежнего размера (увеличьте её resize2fs, xfs_growfs ...).
- У копии те же метки и UUID, что у оригинала. Никогда не монтируйте их
  одновременно: xfs откажется, btrfs может испортить оба.
- Потерянный блок saveset-а -- потерянный кусок устройства:
  восстановление скажет FILDAMAGED. Держите /GROUP_SIZE небольшим и
  две копии важного.

/PHYSICAL берёт один вход и не сочетается с /SELECT, /EXCLUDE, /SINCE,
/BEFORE, /BY_OWNER, /RECORD и /INCREMENTAL: устройство -- не дерево
файлов.

## /IMAGE -- файловая система целиком, пересоздаётся при восстановлении

```
vbackup /mnt/data /mnt/usb/data.bck /IMAGE             сохранить том
vbackup /dev/sdb1 /mnt/usb/data.bck /IMAGE             то же, по устройству
vbackup /mnt/usb/data.bck /dev/sdc1 /IMAGE /REPLACE    создать его заново на устройстве
vbackup /mnt/usb/data.bck /tmp/dir                     только файлы, в каталог
```

Сохраняет все файлы одной файловой системы -- целиком, без других
файловых систем, смонтированных внутри неё, -- и то, что делает её этим
томом: тип, метку, UUID, владельца и права корня. На входе -- точка
монтирования или устройство, если оно смонтировано (хватит и только на
чтение). Запускать от root.

Восстановление с /IMAGE создаёт на выходном устройстве новую файловую
систему того же типа, с той же меткой и UUID (запускается mkfs.ext4,
mkfs.xfs, mkfs.btrfs или mkfs.vfat -- программа должна быть
установлена), восстанавливает в неё файлы и размонтирует. Устройство
может быть меньше или больше сохранённого -- лишь бы файлы поместились.

Защита та же, что у /PHYSICAL: /REPLACE, никогда на смонтированное или
занятое устройство, YES за терминалом; у копии UUID оригинала -- никогда
не монтируйте их одновременно.

Чем /IMAGE не является: копией загрузочных секторов и таблицы разделов
(для этого сохраните весь диск с /PHYSICAL) и номеров inode. Том, на
который пишут во время сохранения, согласован пофайлово, но не между
файлами: если это важно, сохраняйте снимок. Другие типы файловых систем
(minix, ntfs ...): /PHYSICAL.

/IMAGE сочетается с /RECORD, /SINCE, /VERIFY и /DATA_FORMAT; не
сочетается с /SELECT, /EXCLUDE, /BY_OWNER, /INCREMENTAL, /PHYSICAL, а при
восстановлении -- с /CONFIRM.

## /DATA_FORMAT -- сжимать данные

```
/DATA_FORMAT=COMPRESSED
/DATA_FORMAT=UNCOMPRESSED     (по умолчанию)
```

COMPRESSED делает saveset меньше: тексты, программы и документы часто
сжимаются вдвое и сильнее. Уже сжатые файлы (фото, видео, .gz, .zip)
остаются как есть: VBACKUP видит, что они не сжимаются, и пишет их без
сжатия. Контрольные суммы и починка плохих блоков работают как обычно.

Восстановлению, /LIST, /COMPARE, /EXTRACT и vbkx ничего указывать не
надо: сжатые данные они узнают сами.

Внимание: VBACKUP и vbkx версий до X01-04 сжатые данные читать не
умеют. Неверных файлов они не пишут: сжатые файлы они называют
повреждёнными (CRCERR, FILDAMAGED). Обновите их.

Пример: vbackup /home /mnt/usb/home.bck /DATA_FORMAT=COMPRESSED

## /SELECT -- взять только некоторые файлы

```
/SELECT=(шаблон[,...])
```

Берёт только файлы, чьё хранимое имя подходит под шаблон. Работает
при сохранении, восстановлении, сравнении и листинге. В шаблоне *
означает любые символы (и / тоже), % и ? -- один символ:

```
$ vbackup home.bck /tmp/r '/SELECT=(*.c,*.h)'
```

Хранимое имя -- имя относительно базы saveset-а, например
rrl/src/a.c. /LIST показывает хранимые имена.

## /EXCLUDE -- исключить файлы

```
/EXCLUDE=(шаблон[,...])
```

Пропускает файлы, чьё хранимое имя подходит под шаблон. Подходящий
каталог пропускается целиком:

```
$ vbackup /home/rrl rrl.bck '/EXCLUDE=(*.o,*/.cache)'
```

## /SINCE -- только файлы, изменённые после момента

```
/SINCE=время
/SINCE=BACKUP
```

Сохраняет только файлы не старше указанного времени. Каталоги
сохраняются всегда. См. тему ВРЕМЯ.

/SINCE=BACKUP сохраняет только файлы, изменившиеся с тех пор, как их в
последний раз сохранили с /RECORD, -- это знает журнал. Файл, которого
журнал не знает, сохраняется. Без журнала сохраняется всё, как в первый
раз.

Любой /SINCE или /BEFORE делает saveset инкрементальным: файлы, которые
он не сохранил, всё равно перечислены в его каталоге как присутствующие.
См. тему ИНКРЕМЕНТЫ.

## /BEFORE -- только файлы старше момента

```
/BEFORE=время
```

Сохраняет только файлы старше указанного времени. См. тему ВРЕМЯ.

## /MODIFIED -- /SINCE и /BEFORE смотрят на время изменения

Так по умолчанию.

## /CREATED -- /SINCE и /BEFORE смотрят на время создания

Linux хранит время создания на ext4, xfs и btrfs. На файловой системе
без него файлы по этому времени не отбираются.

## /CHANGED -- /SINCE и /BEFORE смотрят на время смены атрибутов

Время смены (ctime) меняется и тогда, когда меняются права, владелец
или имя.

## /BY_OWNER -- только файлы одного пользователя

```
/BY_OWNER=пользователь
```

Сохраняет только файлы этого пользователя -- по имени или номеру.

## /CROSS_DEVICE -- заходить в другие файловые системы

```
/CROSS_DEVICE
/NOCROSS_DEVICE   (по умолчанию)
```

По умолчанию точка монтирования сохраняется как каталог, но то, что на
неё смонтировано, -- нет. Поэтому при сохранении / не попадут /proc,
/sys и подключённая флешка. /CROSS_DEVICE -- сохранить и их.

## /IGNORE -- сохранить то, что обычно пропускается

```
/IGNORE=NOBACKUP
```

Файлы и каталоги с флагом nodump (chattr +d) не сохраняются -- это
флаг NOBACKUP из OpenVMS. /IGNORE=NOBACKUP сохраняет и их.

## /XATTRS -- расширенные атрибуты и ACL

```
/XATTRS     (по умолчанию)
/NOXATTRS
```

Сохраняет и восстанавливает расширенные атрибуты, POSIX ACL,
capabilities файлов и метку SELinux. Часть из них восстановить может
только root.

## /VERIFY -- проверить saveset после записи

Записав saveset, VBACKUP читает его заново и сравнивает каждый файл с
диском. Различие сообщается как %VBACKUP-E-COMPARERR.

## /LOG -- сообщать о каждом файле

Сообщает о каждом сохранённом, восстановленном или сравнённом файле и
об итогах в конце.

## /CONFIRM -- спрашивать перед каждым файлом

Спрашивает на терминале перед каждым файлом: YES, NO, QUIT или ALL.
Пустой ответ -- NO.

## /REPLACE -- перезаписывать существующее

При сохранении: существующий saveset перезаписывается.

При восстановлении: существующий файл удаляется и восстанавливается
заново. Без /REPLACE он остаётся, и вы видите %VBACKUP-W-FILEEXISTS.

При извлечении: существующий выходной файл перезаписывается.

## /OWNER -- кому принадлежат восстановленные файлы

```
/OWNER=ORIGINAL
/OWNER=DEFAULT
/OWNER=пользователь
```

ORIGINAL возвращает файлы их владельцам: по имени, если такое имя есть
на этой машине, иначе по номеру. Так по умолчанию для root.

DEFAULT оставляет файлы вам. Так по умолчанию для всех остальных --
отдать файл другому они всё равно не могут.

пользователь -- все файлы отдаются ему.

## /LIST -- листинг saveset-а

```
/LIST[=файл]
```

Показывает, что лежит в saveset-е: сначала сводку (кто записал, когда,
какой командой), затем файлы. С именем файла листинг пишется в файл.

Список читается из каталога в конце saveset-а, поэтому даже очень
большой saveset показывается сразу.

/LIST можно дать и при сохранении -- будет показан новый saveset.

## /BRIEF -- краткий листинг

Имя, размер и дата каждого файла. Так по умолчанию.

## /FULL -- подробный листинг

Добавляет тип, владельца, права, контрольную сумму и состояние каждого
файла.

## /FORMAT -- вид листинга

```
/FORMAT=VMS   (по умолчанию)
/FORMAT=LS
```

LS -- по строке на файл, как "ls -l", с полным хранимым именем. Для
чтения программами.

## /EXTRACT -- достать один файл

```
/EXTRACT=хранимое-имя
```

Пишет содержимое одного файла в выходную спецификацию или в
стандартный вывод. Имя точное, без шаблонов; /LIST его показывает.
Файл находится через каталог, поэтому это быстро даже в большом
saveset-е.

```
$ vbackup home.bck /EXTRACT=rrl/notes.txt | less
```

## /COMPARE -- сравнить saveset с диском

Читает saveset и сравнивает каждый файл с диском: тип, размер,
содержимое, цель символической ссылки. Различие сообщается как
%VBACKUP-E-COMPARERR, код завершения 2.

## /RECORD -- запомнить, что сохранено

При сохранении: когда saveset записан (а с /VERIFY -- и проверен),
журнал запоминает saveset и для каждого файла, сохранённого без
происшествий, его размер, времена и inode. Следующий /SINCE=BACKUP
сохранит только изменившееся. Файл, который менялся во время сохранения
или не прочитался, не запоминается -- в следующий раз он сохранится
снова.

С saveset-ами и без выхода (vbackup a.bck,b.bck /RECORD): журнал
восстанавливается из их каталогов. Нужно, если журнал потерян.

## /JOURNAL -- какой журнал

```
/JOURNAL[=файл]
```

Журнал -- /var/lib/vbackup/vbackup.jnl для root и
~/.vbackup/vbackup.jnl для остальных. /JOURNAL=файл -- другой журнал,
например свой для каждого плана резервного копирования.

С /LIST и без параметров журнал показывается: какие saveset-ы он знает.
/FULL добавляет файлы и где их последняя копия; /SELECT отбирает файлы
по абсолютному имени:

```
$ vbackup /JOURNAL /LIST /FULL '/SELECT=*/notes.txt'
```

## /INCREMENTAL -- восстановить цепочку saveset-ов

```
$ vbackup full.bck,mon.bck,tue.bck /home /INCREMENTAL
```

Восстанавливает полный saveset, затем каждый инкрементальный, от старых
к новым, и приводит каждый каталог к виду на момент последнего
сохранения: файл, которого более поздний saveset уже не перечисляет,
удаляется. Изменившиеся файлы заменяются -- /INCREMENTAL включает
/REPLACE.

Чистятся только каталоги, которые есть в saveset-е, и никогда сам
выходной каталог. Saveset без каталога или сделанный VBACKUP до X01-02
не принимается (%VBACKUP-E-NOTINCR): по неполному списку ничего не
удаляется. /CONFIRM спрашивает перед каждым удалением, /LOG сообщает о
нём. /SELECT и /EXCLUDE вместе с /INCREMENTAL не принимаются: чистка
задела бы каталоги, которые вы не собирались трогать.

Заметьте: BACKUP в OpenVMS восстанавливает инкрементальную цепочку от
новых к старым; VBACKUP -- от старых к новым.

## /HELP -- показать это описание

```
vbackup /HELP [тема ...]
```

Показывает тему этого описания, например vbackup /HELP /VERIFY.

## Шаблоны -- как раскрывается спецификация файла

```
*      любые символы в одном имени
% ?    один символ
...    любое число уровней каталогов, в том числе ни одного
```

База спецификации -- часть до первого шаблона. Хранимые имена
отсчитываются от неё:

```
/home/rrl                база /home          имена rrl, rrl/...
/home/rrl/src/.../*.c    база /home/rrl/src  имена a.c, lib/b.c
/etc/*.conf              база /etc           имена host.conf, ...
```

Подходящий каталог берётся со всем содержимым. Скрытые файлы (имена с
точки) тоже подходят.

## Инкременты -- сохранять только изменённое

Один раз сделайте полный saveset с /RECORD, потом -- инкрементальные:

```
$ vbackup /home full.bck /RECORD
$ vbackup /home mon.bck /SINCE=BACKUP /RECORD
$ vbackup /home tue.bck /SINCE=BACKUP /RECORD
```

Каждый инкрементальный saveset содержит только файлы, изменившиеся с
последнего /RECORD, но его каталог перечисляет все файлы, какие были, --
поэтому восстановление знает, что удалено. Восстанавливайте все по
порядку:

```
$ vbackup full.bck,mon.bck,tue.bck /restore /INCREMENTAL
```

Что охвачено и что сохранено: /SELECT, /EXCLUDE, флаг nodump,
/NOCROSS_DEVICE и /BY_OWNER говорят, о каких файлах saveset; /SINCE,
/BEFORE и /SINCE=BACKUP -- какие из них сохраняются.

## Время -- как записывается время

```
dd-MMM-yyyy[ hh:mm[:ss]]   3-OCT-2026 14:00
hh:mm[:ss]                 сегодня в это время
-[dd ]hh:mm[:ss]           столько времени назад: "-1 0:0" -- сутки назад
TODAY  YESTERDAY  TOMORROW  NOW
BACKUP                     только /SINCE: с последнего /RECORD каждого файла
```

## Vbkx -- автономный извлекатель

vbkx читает saveset-ы на машине, где VBACKUP не установлен. Это одна
статически собранная программа: скопируйте её туда и запускайте.

```
vbkx l saveset                          список файлов
vbkx x saveset [-C dir] [-f] [name...]  извлечь всё или названные файлы
vbkx p saveset name                     один файл на стандартный вывод
vbkx t saveset                          прочитать всё, проверить суммы
```

Имя -- сохранённое имя, как в списке; имя каталога берёт всё, что в
нём. -C задаёт выходной каталог (создаётся, если его нет); -f
перезаписывает существующие файлы.

vbkx восстанавливает данные, дыры, права, времена, символьные и жёсткие
ссылки, FIFO; от root ещё владельца (по номеру) и файлы устройств. ACL,
расширенные атрибуты и флаги chattr он не восстанавливает: если они
нужны, восстанавливайте через VBACKUP.

Повреждённый saveset чинится, насколько позволяют XOR-блоки. vbkx
называет каждый неполный файл ("is incomplete") и каждый файл, до
которого не добрался ("was not extracted"). Код завершения: 0 --
готово; 1 -- что-то повреждено или не сделано; 2 -- команду или
saveset нельзя использовать.

Есть и vbkx.exe для Windows, с теми же командами. Он восстанавливает
данные, времена, файлы только для чтения, каталоги и жёсткие ссылки;
символьные ссылки -- только где Windows их разрешает. Имя, которое
Windows не принимает (с : ? * и т.п., или CON, NUL ...), не
извлекается, и об этом сказано.

## Примеры

Сохранить домашний каталог, проверить, посмотреть:

```
$ vbackup /home/rrl /backup/rrl.bck /VERIFY
$ vbackup /backup/rrl.bck /LIST
```

Восстановить в другое место:

```
$ vbackup /backup/rrl.bck /tmp/restore
```

Сохранить только изменённое сегодня, томами по 4 ГБ:

```
$ vbackup /home /mnt/usb/home.bck /SINCE=TODAY /VOLUME_SIZE=4G
```

Восстановить только исходники на C, перезаписывая существующие:

```
$ vbackup /backup/rrl.bck /home '/SELECT=*.c' /REPLACE
```

Скопировать дерево на другой диск и проверить копию:

```
$ vbackup /home/rrl /mnt/disk2 /VERIFY
```

Отправить saveset на другую машину:

```
$ vbackup /etc - | ssh backup-host 'cat > etc.bck'
```

## Неполадки -- что делать, если

**Saveset не создаётся: %VBACKUP-E-OPENOUT ... errno=17 (File
exists).** Saveset с таким именем уже есть. Дайте другое имя или
/REPLACE, чтобы перезаписать.

**%VBACKUP-E-IVOP, cannot tell what to do.** Вход -- не saveset, а
выход на saveset не похож. При сохранении дайте /SAVE_SET или имя с
окончанием .bck.

**%VBACKUP-I-BLKFIXED при восстановлении.** Блок saveset-а был
испорчен и исправлен. Все файлы в порядке. Возможно, носитель
умирает: скопируйте saveset на другой.

**%VBACKUP-E-BLKLOST и %VBACKUP-E-FILDAMAGED.** Блоки потеряны и не
могут быть исправлены. Файлы, названные в FILDAMAGED, неполные;
файлы, названные в FILLOST, не восстановлены вовсе; все остальные в
порядке. В следующий раз дайте меньший /GROUP_SIZE (больше XOR-блоков)
или храните две копии важных saveset-ов.

**%VBACKUP-W-UNNAMED.** Блоки потеряны, а каталога у saveset-а нет или
он тоже повреждён. Каких-то файлов в выходном каталоге может не быть,
и VBACKUP не может назвать их все. Сравните результат с источником
или с /LIST более старого saveset-а.

**%VBACKUP-E-MISSVOL.** Не хватает тома. Сложите все тома в один
каталог, не меняя имён.

**%VBACKUP-W-NOTRAILER.** Сохранение не завершилось (кончилось место,
программу остановили) или нет последнего тома. Файлы до места обрыва
восстанавливаются. /LIST работает медленнее -- читает весь saveset.

**%VBACKUP-W-FILCHANGED при сохранении.** В файл писали во время
сохранения; копия может быть смесью старого и нового. Сохраните его,
когда никто не пишет, или со снапшота.

**%VBACKUP-W-ATTRERR при восстановлении.** Не удалось поставить
владельца, права, время, атрибут или флаг. Чаще всего -- вы не root:
восстанавливайте под root или дайте /OWNER=DEFAULT.

**%VBACKUP-E-OPENOUT ... a name that leads out of the output
directory.** В saveset-е есть имя с ".." или с "/" в начале, или имя,
идущее через символическую ссылку. Такой файл никогда не пишется.
Saveset сделан не VBACKUP-ом или сделан во вред.

**/SINCE=BACKUP сохраняет всё.** Журнал не знает этих файлов:
сохранения делались без /RECORD, с другим /JOURNAL или от другого
пользователя (у каждого свой журнал). Посмотрите vbackup /JOURNAL /LIST.

**%VBACKUP-E-NOTINCR.** /INCREMENTAL нужен saveset с каталогом,
сделанный VBACKUP X01-02 или новее. Такой восстанавливайте без
/INCREMENTAL.

**%VBACKUP-W-MISSING.** Файл должен был остаться от более раннего
saveset-а цепочки, а его нет. Чаще всего пропущен saveset цепочки: дайте
все, от старых к новым.

**%VBACKUP-E-JNLERR.** Журнал не читается или не пишется -- причина в
сообщении. Испорченный журнал можно восстановить: удалите его и дайте
saveset-ы с /RECORD.

**Из каталога ничего не сохраняется.** Проверьте флаг nodump:
lsattr -d каталог. /IGNORE=NOBACKUP -- сохранить всё равно.

**Сохранение идёт медленно, или нужно понять, не виноват ли поток
записи.** Saveset пишет отдельный поток, пока читаются файлы. Задайте в
окружении VBACKUP_PIPELINE=0, чтобы писать без этого потока:
VBACKUP_PIPELINE=0 vbackup /home h.bck. Выключается только поток,
подсказки кэшу страниц остаются. Saveset получится тот же. Если
проблема ушла, сообщите о ней.

Ещё восемь потоков заранее читают следующие файлы, пока сохраняется
или копируется текущий, чтобы сохранение находило их в кэше.
VBACKUP_PREFETCH=n задаёт число потоков, 0 выключает опережающее
чтение. На NFS или медленном сетевом диске может помочь больше потоков,
на одном медленном жёстком диске -- меньше.

**После сохранения файлов нет в кэше страниц.** Так задумано. VBACKUP
выбрасывает из кэша страницы saveset-а, который пишет или читает, и
страницы файла, которого в кэше не было до чтения. Файлы, которые были
в кэше, там и остаются.
