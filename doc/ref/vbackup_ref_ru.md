## Глава 1 Описание VBACKUP

Утилита VBACKUP сохраняет файлы и каталоги файловых систем Linux в
*saveset*, восстанавливает их из него, выводит его содержимое и сравнивает
его с диском. Кроме того, она копирует файлы с диска на диск, копирует
блочное устройство поблочно, сохраняет и заново создаёт целую файловую
систему и ведёт журнал для инкрементного сохранения. VBACKUP следует
утилите BACKUP системы OpenVMS: одна команда, два параметра, и операция
определяется тем, что представляют собой параметры.

VBACKUP не требует в системе ничего, кроме библиотеки C; saveset-ы можно
прочитать и без VBACKUP -- автономным распаковщиком vbkx и распаковщиками
последней надежды (приложение C).

### 1.1 Saveset-ы

Saveset -- это файл или набор файлов, называемых *томами*, содержащий копии
файлов вместе со всем, что нужно для их возврата:

- данные обычных файлов, разреженные файлы с их дырами;
- каталоги, символические ссылки, жёсткие ссылки, FIFO, файлы символьных и
  блочных устройств;
- владелец и группа -- по номеру и по имени;
- режим доступа, включая биты setuid, setgid и sticky;
- времена изменения, доступа, смены атрибутов и создания, с наносекундами;
- расширенные атрибуты, списки POSIX ACL, возможности (capabilities)
  файлов и метка SELinux;
- флаги файловой системы `chattr` (FS_IOC_GETFLAGS).

Помимо файлов, saveset содержит сводку сохранения (продукт, узел,
пользователь, команда, время, базы входных спецификаций, размеры блока и
группы, операционная система), контрольную сумму каждого блока и каждого
файла, блоки XOR для починки и каталог своих файлов.

На входной стороне VBACKUP распознаёт saveset по содержимому, а не по
имени. На выходной стороне сохранения saveset распознаётся по имени
(оканчивается на `.bck` или `.sav`), по квалификатору `/SAVE_SET` или по имени
`-` (стандартный вывод).

### 1.2 Операции

Операция определяется параметрами и несколькими квалификаторами (см.
главу 2, «Сводка по использованию»):

| Вход | Выход | Операция |
|---|---|---|
| файлы | saveset | **Сохранение**: файлы записываются в новый saveset. |
| saveset[,...] | каталог | **Восстановление**: файлы saveset-а создаются в каталоге. |
| saveset | -- (с `/ORIGINAL`) | **Восстановление** каждого файла в каталог, из которого он был сохранён. |
| saveset | -- (с `/LIST`) | **Листинг**: выводятся сводка и файлы saveset-а. |
| saveset | [каталог] (с `/COMPARE`) | **Сравнение**: каждый файл saveset-а сравнивается с диском. |
| saveset | [файл] (с `/EXTRACT`) | **Извлечение**: один файл записывается в файл или на стандартный вывод. |
| файлы | каталог (не saveset) | **Копирование**: файлы копируются с диска на диск. |
| saveset[,...] | -- (с `/RECORD`) | **Перестройка журнала**: журнал создаётся заново по каталогам saveset-ов. |
| -- | -- (с `/JOURNAL /LIST`) | **Листинг журнала**: известные журналу saveset-ы и файлы. |

Сохранение может также проверить новый saveset (`/VERIFY`), вывести его
листинг (`/LIST`), записать его в журнал (`/RECORD`) и удалить сохранённые и
проверенные файлы (`/DELETE`).

### 1.3 Структура saveset-а

#### Блоки

Saveset -- последовательность блоков одного фиксированного размера,
*размера блока* (`/BLOCK_SIZE`, от 8192 до 1048576 байт, кратен 512; по
умолчанию 65536). Каждый блок начинается 64-байтным заголовком, который
содержит идентификатор saveset-а (случайный UUID), номер блока, номер
тома, тип блока и CRC-32 заголовка и полезной нагрузки. Блоки нумеруются
с 0 непрерывно через все тома. Первый блок каждого тома -- *заголовок тома*
(VHDR) со сводкой saveset-а, так что каждый том сам указывает, что он
такое и к какому saveset-у относится.

Полезные нагрузки блоков данных, взятые по порядку, образуют один поток
записей: запись SUMMARY, затем для каждого файла запись FILE, его записи
DATA (или сжатые DATAZ) и запись FEND с размером, CRC данных и состоянием
файла; затем записи CATALOG и запись END. Запись может пересекать границы
блоков и томов.

#### CRC

Каждый блок несёт CRC-32 (IEEE) своего заголовка и нагрузки; каждый файл
несёт CRC-32 своих данных в записи FEND и в элементе каталога.
Повреждённый блок при чтении saveset-а обнаруживается всегда; файл, данные
которого не совпадают с его CRC, сообщается (CRCERR) и никогда молча не
восстанавливается как исправный.

#### Группы XOR и починка

После каждых *n* блоков данных (*n* -- *размер группы*, `/GROUP_SIZE`, от 0 до
100, по умолчанию 10) VBACKUP пишет один блок XOR -- побайтовое XOR
нагрузок блоков данных группы. Если при чтении saveset-а в группе
испорчен ровно один блок данных, он восстанавливается из остальных блоков
группы и блока XOR и выводится сообщение BLKFIXED; ничего не теряется. Если
испорчены два блока группы или больше, о них сообщается (BLKLOST); чтение
продолжается с первой записи, начинающейся в следующем исправном блоке, и
страдают только файлы, данные которых лежали в потерянных блоках
(FILDAMAGED, FILLOST). `/GROUP_SIZE=0` не пишет блоков XOR, и ничего нельзя
починить. Блоки XOR при размере группы по умолчанию увеличивают saveset
примерно на 10%.

#### Тома и их имена

`/VOLUME_SIZE` разрезает saveset на тома фиксированного размера. Том 1 имеет
имя, заданное в команде; том *k* (*k* >= 2) -- это имя, точку и *k* в
десятичной записи, не менее трёх цифр:

```
home.bck  home.bck.002  home.bck.003  ...
```

Размер тома округляется вниз до кратного размеру блока; каждый том, кроме
последнего, имеет ровно этот размер. Группа блоков никогда не пересекает
границу тома. Чтобы прочитать saveset, укажите имя его первого тома;
остальные VBACKUP найдёт рядом. Об отсутствующем томе сообщается (MISSVOL);
файлы, целиком лежащие в остальных томах, всё равно восстанавливаются.
Файл с именем тома, принадлежащий другому saveset-у, пропускается
(WRONGVOL).

#### Каталог

В конце потока VBACKUP пишет каталог: по элементу на каждый файл, с его
именем, типом, владельцем, режимом, размером, временами, целью ссылки, CRC,
состоянием и местом (том, блок, смещение), где начинается его запись FILE.
`/LIST` читает только каталог, поэтому даже очень большой saveset выводится
сразу; `/EXTRACT` добирается до одного файла по его месту в каталоге, не
читая ничего другого. Каталог инкрементного saveset-а перечисляет и файлы,
которые им охвачены, но не сохранены, с состоянием PRESENT (см. раздел 1.5).

#### TRAILER

Последний блок saveset-а -- TRAILER. В нём итоги сохранения (файлы, байты,
ошибки, блоки, тома, элементы каталога) и место начала каталога. Saveset
без TRAILER -- сохранение прервано, диск переполнился или отсутствует
последний том -- всё равно читается последовательно до последнего исправного
блока; VBACKUP сообщает NOTRAILER, а `/LIST` читает весь saveset (NOCATALOG).

### 1.4 Спецификации файлов и шаблоны

Входная спецификация сохранения или копирования -- имя файла или каталога,
возможно с шаблонами. VBACKUP раскрывает шаблоны сам; заключайте их в
кавычки, чтобы их не раскрыл командный интерпретатор:

| Шаблон | Соответствует |
|---|---|
| `*` | любые символы в пределах одного компонента имени |
| `%` `?` | ровно один символ |
| `...` | любое число уровней каталогов, в том числе ни одного (как целый компонент) |

*База* спецификации -- часть до первого компонента, содержащего шаблон или
`...`; без шаблонов база -- каталог, содержащий названный файл или каталог.
Имена, хранимые в saveset-е, -- *хранимые имена* -- задаются относительно
базы. Поэтому каталог, названный в спецификации, хранится со своим именем
впереди:

| Спецификация | База | Хранимые имена |
|---|---|---|
| `/home/rrl` | `/home` | `rrl`, `rrl/...` |
| `/home/rrl/src/.../*.c` | `/home/rrl/src` | `a.c`, `lib/b.c` |
| `/etc/*.conf` | `/etc` | `host.conf`, ... |
| `/mnt/data/.` | `/mnt/data/.` | содержимое `/mnt/data` под собственными именами |

Каталог, выбранный спецификацией, берётся со всем содержимым. Скрытые файлы
(имена, начинающиеся с точки) тоже подходят под шаблоны. Элементы каталога
обходятся в байтовом порядке их имён, так что два сохранения одного дерева
дают одинаковое расположение saveset-а. Базы записываются в сводку как
абсолютные имена (realpath); ими пользуются `/ORIGINAL` и `/COMPARE` без
выходного параметра.

Шаблоны `/SELECT` и `/EXCLUDE` сопоставляются с хранимыми именами. В шаблоне
`*` соответствует любым символам, включая `/`, а `%` и `?` -- одному символу.

Слово команды, начинающееся с косой черты, является квалификатором, только
если оно называет квалификатор; `/etc` и `/home` -- имена файлов.
Спецификация с шаблоном никогда не принимается за saveset.

### 1.5 Инкрементное сохранение и журнал

VBACKUP различает в saveset-е два множества файлов (`format.md`, 6.6):

- *охваченное* множество: все элементы, выбранные входными спецификациями и
  фильтрами имён -- `/SELECT`, `/EXCLUDE`, флагом nodump, `/NOCROSS_DEVICE` --
  и квалификатором `/BY_OWNER`;
- *сохранённое* множество: та часть охваченного, данные которой есть в
  saveset-е. В *полном* saveset-е это само охваченное множество. В
  *инкрементном* его выбирают фильтры времени -- `/SINCE`, `/BEFORE`,
  `/SINCE=BACKUP`.

Любой фильтр времени делает saveset инкрементным. Его каталог перечисляет
всё охваченное множество: сохранённые файлы с их состоянием, остальные --
как PRESENT. Тем самым каталог описывает дерево таким, каким оно было в
момент сохранения, и восстановление `/INCREMENTAL` может удалить из каталога
то, чего в нём уже не было. Каталоги сохраняются всегда.

*Журнал* -- отдельный файл вне любого saveset-а. Сохранение с `/RECORD`
записывает в него saveset и, для каждого файла, сохранённого с состоянием
OK, его абсолютное имя, inode, размер, время изменения и время смены
атрибутов. Сохранение с `/SINCE=BACKUP` сохраняет файл, если журнал его не
знает или если его inode, время смены атрибутов, время изменения или размер
отличаются от записанных; номер устройства записывается, но не
сравнивается. Файл, сохранённый в состоянии CHANGED или с ошибкой чтения,
не записывается, поэтому следующее `/SINCE=BACKUP` сохранит его снова. При
`/VERIFY` журнал обновляется, только если проверка не нашла различий.

Журнал -- `/var/lib/vbackup/vbackup.jnl` для root и `~/.vbackup/vbackup.jnl`
для остальных пользователей; `/JOURNAL=файл` задаёт другой. Он
переписывается целиком под исключительной блокировкой (`журнал.lock`) через
`журнал.tmp`. Потерянный или испорченный журнал можно перестроить по
каталогам saveset-ов (`saveset[,...] /RECORD`); журнал -- удобство, а не
единственная копия чего бы то ни было.

Цепочка -- полный saveset, затем инкрементные в порядке их создания --
восстанавливается с `/INCREMENTAL`. Заметьте: OpenVMS BACKUP восстанавливает
инкрементную цепочку начиная с новейшего saveset-а; VBACKUP -- начиная со
старейшего.

### 1.6 Физические операции и операции над образом

#### /PHYSICAL

Сохранение `/PHYSICAL` копирует каждый блок одного блочного устройства --
раздела или целого диска -- или файла образа, что бы на нём ни было: любую
файловую систему, зашифрованный том, загрузочные области. Saveset содержит
один обычный файл -- образ устройства, названный по узлу устройства;
куски по 65536 байт, состоящие из одних нулей, не записываются. VBACKUP
отвергает устройство, смонтированное на чтение и запись (или раздел
которого смонтирован так), и устройство, занятое (удерживаемое LVM, RAID,
dm-crypt или используемое как swap). Устройство, смонтированное только на
чтение, принимается.

Восстановление `/PHYSICAL` записывает образ на устройство или в файл образа.
На устройство оно требует `/REPLACE`, отвергает смонтированное или занятое
устройство и устройство меньше сохранённого, пишет нули в промежутки и на
терминале спрашивает `YES`. На устройство большего размера записывается
начальная часть, остальное остаётся как было. Копия несёт метки и UUID
оригинала (PHYSUUID): никогда не монтируйте оба одновременно.

Saveset `/PHYSICAL`, восстановленный без `/PHYSICAL`, -- это разреженный файл
образа в выходном каталоге; так его восстанавливает любой распаковщик.

#### /IMAGE

Сохранение `/IMAGE` сохраняет каждый файл одной смонтированной файловой
системы -- ничего из файловых систем, смонтированных ниже, флаги nodump
игнорируются -- под именами относительно её корня и записывает то, что
делает том этим томом: тип, метку, UUID, занятое место, параметры
монтирования и владельца, режим, времена и ACL её корневого каталога. Вход
-- точка монтирования или устройство, если оно смонтировано (достаточно
только на чтение).

Восстановление `/IMAGE` на устройство создаёт новую файловую систему
сохранённого типа, с той же меткой и UUID, запуская `mkfs.ext2`, `mkfs.ext3`,
`mkfs.ext4`, `mkfs.xfs`, `mkfs.btrfs` или `mkfs.vfat` (программа должна быть
установлена), монтирует её во временный каталог с `nosuid,nodev,noexec`,
восстанавливает в неё файлы, придаёт её корню сохранённые атрибуты и
размонтирует. Защиты -- те же, что у `/PHYSICAL`; устройство должно вмещать
занятое место плюс 5% плюс 16 МБ и может быть меньше или больше
сохранённого. `/IMAGE` не копирует ни загрузочные сектора, ни таблицу
разделов, ни номера inode; для этого используйте `/PHYSICAL` целого диска.

Saveset `/IMAGE`, восстановленный без `/IMAGE`, -- обычное дерево файлов.

### 1.7 Сжатие

`/DATA_FORMAT=COMPRESSED` хранит данные файлов в записях DATAZ, сжатых в
блочном формате LZ4. Для каждого куска VBACKUP сначала пробует первые
64 КБ и хранит кусок несжатым, если он сжимается меньше чем на 3%; уже
сжатые данные (фотографии, видео, `.gz`, `.zip`) почти не стоят времени.
Запись DATAZ пишется, только если она меньше, чем была бы запись DATA.
Контрольные суммы и починка работают так же, как для несжатых данных: CRC
файла -- это CRC исходных байтов, CRC блока -- байтов в том виде, в каком
они лежат в потоке.

Сжатие выполняется в нескольких потоках (см. раздел 1.11); saveset байт в
байт тот же, что и с одним потоком. Восстановление, `/LIST`, `/COMPARE`,
`/EXTRACT` и все распаковщики распознают сжатые данные сами.

VBACKUP и vbkx версий до X01-04 не читают сжатые данные; они сообщают о
сжатых файлах как о повреждённых (CRCERR, FILDAMAGED) и никогда молча не
записывают неверные данные.

### 1.8 Шифрование

`/ENCRYPT` создаёт зашифрованный saveset (`format.md`, 6.10). Нагрузки блоков
данных и TRAILER шифруются ChaCha20 и аутентифицируются HMAC-SHA256, каждый
блок -- 32-байтным тегом. Ключи выводятся из пароля функцией
PBKDF2-HMAC-SHA256, по умолчанию 600000 итераций, со случайной 32-байтной
солью, новой для каждого saveset-а. Криптографическая библиотека не
используется: vbkx и распаковщики последней надежды читают зашифрованные
saveset-ы без чего-либо ещё.

#### Ключи и KEYCHECK

Из пароля и соли VBACKUP выводит главный ключ, а из него -- три ключа: для
шифрования, для аутентификации и контрольное значение. Контрольное
значение хранится в заголовке тома как KEYCHECK. Читающий выводит ключи и
сравнивает контрольное значение, прежде чем читать что-либо ещё:
несовпадение означает неверный пароль (WRONGKEY), а не повреждение
saveset-а.

#### Что остаётся видимым

Заголовки блоков, CRC и блоки XOR вычисляются по шифротексту, поэтому
повреждённый зашифрованный saveset проверяется и чинится без пароля. Без
пароля видны: размер блока, размер группы, размер тома и число томов; длина
потока и места начала записей в каждом блоке; время сохранения -- лишь по
временам файлов томов. Не видны: имена, размеры, атрибуты и содержимое
файлов, узел, пользователь, команда и итоги TRAILER.

Блок с верным CRC, но неверным тегом изменён умышленно (или очень странным
носителем): о нём сообщается (BLKFORGED), и он считается плохим блоком --
чинится по группе, когда это возможно, иначе теряется.

#### Обращение с паролем

Пароль никогда не берётся из командной строки: команда хранится в
saveset-е и видна другим пользователям через `ps`. Он получается в таком
порядке:

1. из файла ключа, заданного `/KEY_FILE=файл`;
2. из файла ключа, названного переменной окружения `VBACKUP_KEY_FILE`;
3. с терминала (`/dev/tty`), без эха; при сохранении он запрашивается
   дважды, и ответы должны совпасть (иначе KEYMATCH, и ничего не
   сохраняется).

Если нет ни файла ключа, ни терминала (cron, канал, файловый менеджер)
или задано `VBACKUP_NOPROMPT=1`, VBACKUP завершается с NOKEY; он никогда не
ждёт. Пароль запрашивается один раз на команду и сохраняется для
последующих saveset-ов (проверки после сохранения, цепочки восстановления
`/INCREMENTAL`); при выходе и по Ctrl/C он стирается из памяти, и эхо
терминала восстанавливается.

#### Файлы ключа

Пароль -- первая строка файла ключа без признака конца строки (LF или CR
LF), байт в байт; не длиннее 1024 байт и не пустая. Файл ключа должен быть
обычным файлом, доступным на чтение и запись только владельцу (режим 600);
иначе он отвергается (KEYFILE).

Пароль *и есть* ключ: saveset, пароль которого утерян, не откроет никто.
Используйте длинный пароль -- пять или более случайных слов. Журнал не
шифруется: это файл сохраняющей системы.

Открытие зашифрованного saveset-а стоит вычисления PBKDF2: около 0,5 с на
ПК, 1,6 с на небольшой плате ARM с инструкциями SHA, 6 с -- без них. Эта
цена намеренна: её платит и каждая попытка подбора.

VBACKUP и vbkx версий до X01-06 не читают зашифрованные saveset-ы; они
сообщают о потере всех блоков и ничего не записывают.

### 1.9 Каналы

Имя `-` означает стандартный вывод как выход сохранения и стандартный ввод
как вход восстановления, `/LIST`, `/COMPARE` и `/EXTRACT`:

```
$ vbackup /home - | ssh host 'cat > /backup/home.bck'
$ ssh host 'vbackup /home -' | vbackup - /restore
```

Saveset, записываемый в `-`, -- один том; `/VOLUME_SIZE` отвергается
(QUALUSE). Он не проверяется: `/VERIFY` пропускается, `/DELETE` ничего не
удаляет (SRCKEPT), листинг `/LIST` после сохранения не выводится.

Saveset из `-` читается один раз и только вперёд. Каталог в его конце
бесполезен: `/LIST` выводит записи FILE по мере поступления, `/EXTRACT`
ищет свой файл чтением, vbkx отвергает имена. Плохие блоки чинятся так же,
как в файле. Канал, оборвавшийся до TRAILER, даёт NOTRAILER.

### 1.10 Кэш страниц

VBACKUP старается не вытеснять рабочие данные системы из кэша страниц:

- saveset пишется окнами по 8 МБ: запись каждого окна на диск запускается
  сразу, её завершения ждут одним окном позже, после чего страницы
  выбрасываются; каждый том при закрытии синхронизируется;
- тома читаемого saveset-а и сохраняемые файлы читаются с указанием
  последовательного доступа; прочитанная группа saveset-а выбрасывается из
  кэша;
- сохраняемый файл выбрасывается из кэша вслед за чтением, только если его
  в кэше до того не было (ни одна страница его первого мегабайта не
  находилась в памяти); файл, который был в кэше, -- чьи-то рабочие данные,
  он остаётся.

Поэтому после сохранения страниц saveset-а и «холодных» файлов в кэше нет;
это сделано намеренно.

### 1.11 Потоки

| Поток(и) | Работа | Число |
|---|---|---|
| Записи | Пишет блоки saveset-а, пока основной поток читает файлы и строит блоки. | 1; `VBACKUP_PIPELINE=0` -- запись без него. |
| Опережающего чтения | Открывает следующие файлы обхода и читает их первый мегабайт, чтобы сохранение или копирование нашло их в кэше; вперёд не более 128 файлов и 64 МБ. | 8 по умолчанию; `VBACKUP_PREFETCH=n`, не более 64, 0 -- нет. |
| Сжатия | Сжимают данные сохранения `/DATA_FORMAT=COMPRESSED`; основной поток пишет записи по порядку. | По числу процессоров, не более 8; `VBACKUP_ZTHREADS=n`, 1 -- нет. |
| Шифрования | Запись: ключевой поток ChaCha20 блока полосами. Чтение: проверка тегов блоков группы и их расшифровка параллельно. | По числу процессоров, не более 8; `VBACKUP_CTHREADS=n`, 1 -- нет. |

Ни один поток не меняет saveset: при любом числе потоков один и тот же
вход даёт один и тот же saveset.

### 1.12 Автономный распаковщик и распаковщики последней надежды

vbkx -- небольшая статически скомпонованная программа, которая выводит
листинг, извлекает, печатает и проверяет saveset-ы на машине, где VBACKUP
не установлен, -- в системе восстановления, в другом дистрибутиве. Ей не
нужны ни библиотека справки, ни средство сообщений. Она восстанавливает
данные, дыры, режимы, времена, символические и жёсткие ссылки и FIFO, а
под root -- владельцев (по номеру) и файлы устройств; ACL, расширенные
атрибуты и флаги chattr она не восстанавливает. `vbkx.exe` -- та же
программа для Windows.

Ещё три распаковщика -- vbkx-go (Go), vbkx-rs (Rust) и vbkx-pl (Perl) --
написаны на тот день, когда всё остальное умерло: по одному исходному
файлу, только стандартная библиотека, просто, чтобы их можно было прочесть
и исправить по `format.md`. Они читают сжатые и зашифрованные saveset-ы,
чинят один плохой блок на группу и называют каждый повреждённый или
недостающий файл. См. приложение C.

### 1.13 Модули файловых менеджеров

Saveset-ы можно просматривать как папки в Midnight Commander (сценарий
extfs `uvbk`), far2l и Far Manager 3 (MultiArc, поверх vbkx), Total Commander
и Double Commander (модуль упаковщика WCX). Все модули работают только на
чтение: saveset никогда не изменяется. Листинг берётся из каталога, поэтому
даже saveset в сотни гигабайт открывается сразу. Зашифрованный saveset
открывается с файлом ключа, названным в `VBACKUP_KEY_FILE`; модули никогда
не спрашивают пароль. См. приложение D.

## Глава 2 Сводка по использованию VBACKUP

Утилита VBACKUP сохраняет файлы в saveset-ы, восстанавливает, выводит,
сравнивает и извлекает их, копирует файлы с диска на диск, копирует блочные
устройства и целые файловые системы и ведёт журнал инкрементного
сохранения.

### Формат

```
vbackup input-specifier[,...] output-specifier [/qualifiers]
vbackup input-specifier /LIST[=file] [/qualifiers]
vbackup input-specifier [output-specifier] /COMPARE [/qualifiers]
vbackup input-specifier [output-specifier] /EXTRACT=stored-name [/qualifiers]
vbackup input-specifier /ORIGINAL [/qualifiers]
vbackup saveset[,...] /RECORD [/JOURNAL=file]
vbackup /JOURNAL[=file] /LIST [/FULL] [/SELECT=(pattern[,...])]
vbackup /HELP [topic ...]
```

### Параметры

#### input-specifier[,...]

Задаёт вход операции одним словом; несколько спецификаций разделяются
запятыми без пробелов. Элемент в двойных кавычках берётся как есть.

- **Сохранение, копирование:** сохраняемые или копируемые файлы и каталоги,
  возможно с шаблонами (см. раздел 1.4). Каталог берётся со всем
  содержимым. Не более 64 спецификаций.
- **Сохранение /PHYSICAL:** одно блочное устройство или файл образа.
- **Сохранение /IMAGE:** одна точка монтирования или одно смонтированное
  блочное устройство.
- **Восстановление, листинг, сравнение, извлечение, перестройка журнала:**
  saveset, заданный именем первого тома; остальные тома ищутся рядом. Для
  восстановления и перестройки журнала можно задать несколько saveset-ов;
  они обрабатываются по очереди. Для восстановления `/INCREMENTAL` задайте
  сначала полный saveset, затем инкрементные в порядке их создания.
- **`-`:** saveset со стандартного ввода (восстановление, `/LIST`, `/COMPARE`,
  `/EXTRACT`).

Saveset распознаётся по содержимому. Вход с шаблоном или `...` никогда не
бывает saveset-ом.

#### output-specifier

Задаёт выход операции.

- **Сохранение:** создаваемый saveset: имя на `.bck` или `.sav`, любое имя с
  `/SAVE_SET` или `-` для стандартного вывода. Если saveset существует,
  VBACKUP останавливается (OPENOUT, errno 17), если не задан `/REPLACE`.
- **Восстановление:** каталог, в который ведётся восстановление; при
  необходимости он создаётся. Завершающие косые черты игнорируются. С
  `/ORIGINAL` не задаётся.
- **Восстановление /PHYSICAL:** выходное блочное устройство или файл образа.
- **Восстановление /IMAGE:** выходное блочное устройство.
- **Сравнение:** каталог, с которым ведётся сравнение. Если он не задан,
  каждый файл сравнивается с местом, откуда был сохранён (базы
  saveset-а).
- **Извлечение:** записываемый файл. Если он не задан или равен `-`, файл
  идёт на стандартный вывод.
- **Копирование:** каталог, в который ведётся копирование. Выход, не
  являющийся именем saveset-а, при входе, не являющемся saveset-ом,
  означает копирование.
- **Листинг, перестройка журнала, листинг журнала:** нет.

Принимаются только эти два параметра. Третье слово -- ошибка (MAXPARM);
чаще всего это квалификатор, набранный без косой черты.

### Сводка по использованию

VBACKUP вызывается из командного интерпретатора. Квалификаторы можно
ставить в любом месте командной строки -- до, между или после параметров.
Квалификатор можно сокращать, пока сокращение однозначно (`/VER` вместо
`/VERIFY`); неоднозначное сокращение -- ошибка. Квалификатор можно писать и
по-юниксовому, `--VERIFY`; регистр букв не важен. Слово, начинающееся с
косой черты, является квалификатором, только если называет квалификатор,
поэтому `/etc` и `/home` -- имена файлов. Одиночное `--` завершает
квалификаторы: каждое слово после него -- параметр. `-h` равносильно
`/HELP`.

Квалификаторы можно «приклеивать» к параметру, как в DCL: `x.sav/sav/log` --
это `x.sav /SAVE_SET /LOG`. VBACKUP сообщает об этом (GLUED), чтобы опечатка
в имени файла не была незаметно принята за квалификатор. Слово, являющееся
именем существующего файла, никогда не разрезается; квалификатор, значение
которого содержит косую черту (`/JOURNAL=/var/...`), нужно писать отдельно.

Шаблоны раскрывает сам VBACKUP; заключайте их в кавычки, как и значения
квалификаторов, содержащие скобки или `*`:

```
$ vbackup '/home/rrl/.../*.c' sources.bck '/EXCLUDE=(*.o,*/.cache)'
```

#### Как определяется операция

VBACKUP рассматривает параметры в следующем порядке:

1. Проверяется каждый вход. Вход с шаблоном -- не saveset; любой другой вход
   является saveset-ом, если об этом говорит его содержимое.
2. Задан `/EXTRACT` -- извлечение. Задан `/COMPARE` -- сравнение. Оба требуют
   ровно одного входа, и он должен быть saveset-ом (иначе NOTSAVESET).
3. Все входы -- saveset-ы: `/LIST` без выхода -- листинг; `/RECORD` без
   выхода -- перестройка журнала; иначе -- восстановление.
4. Выход -- имя saveset-а (`.bck`, `.sav`, `/SAVE_SET` или `-`): сохранение.
5. Выход задан и входы существуют: копирование.
6. Параметров нет совсем, заданы `/JOURNAL` и `/LIST`: листинг журнала.

В остальных случаях VBACKUP сообщает, чего не хватает: OPENIN, если вход не
существует и выход не задан; NOPARAM, если не задан выход; IVOP, если вход
не существует, а выход не является именем saveset-а. Без параметров и
квалификаторов VBACKUP выводит краткую справку по использованию.

#### Начало и завершение

Каждая операция, кроме листинга, сообщает о своём начале (STARTED) и
завершении (COMPLETED) с затраченным временем и итогом: `completed`,
`completed with warnings` или `completed with errors`. Сохранение,
восстановление, сравнение и копирование сообщают также итоги (SAVESUMM,
RESTSUMM, CMPSUMM, CPYSUMM) и без `/LOG`. `/LOG` добавляет сообщение о каждом
файле.

#### Сообщения

Все сообщения пишутся на стандартный вывод ошибок, по одному в строке, в
виде

```
dd-mm-yyyy hh:mm:ss.cc pid %VBACKUP-s-IDENT, text
```

На стандартный вывод идёт только то, что производит операция: листинг,
данные `/EXTRACT`, saveset, записываемый в `-`, текст справки. См.
приложение A.

#### Код завершения

| Значение | Смысл |
|---|---|
| 0 | Всё сделано. Ни одного предупреждения или ошибки. |
| 1 | Всё сделано, с предупреждениями: выдано хотя бы одно сообщение уровня W (например, файл изменился во время сохранения, файл существует и не восстановлен). |
| 2 | Что-то не сделано: выдано хотя бы одно сообщение уровня E или F (например, файл не удалось прочитать, `/COMPARE` или `/VERIFY` нашли различие) либо команду не удалось разобрать. |

Информационные сообщения и сообщения об успехе на код завершения не
влияют.

### Ограничения

#### Привилегии

- Привилегии root нужны, чтобы восстановить файлы с исходными владельцами
  (`/OWNER=ORIGINAL` -- умолчание только для root), восстановить файлы
  устройств, установить некоторые расширенные атрибуты (`trusted.*`,
  `security.*`, возможности файлов) и некоторые флаги chattr (immutable,
  append-only), а также чтобы читать файлы, недоступные пользователю.
- Операции `/PHYSICAL` и `/IMAGE` над блочными устройствами требуют root: они
  открывают устройства, а восстановление `/IMAGE` запускает `mkfs` и
  монтирует новую файловую систему.
- Пользователь, не являющийся root, восстанавливает файлы как свои
  (`/OWNER=DEFAULT`); о владельцах и атрибутах, которые не удалось
  установить, сообщается (ATTRERR).

#### Пределы

| Параметр | Предел |
|---|---|
| Размер блока (`/BLOCK_SIZE`) | от 8192 до 1048576 байт, кратно 512 |
| Размер группы (`/GROUP_SIZE`) | от 0 до 100 блоков данных |
| Размер тома (`/VOLUME_SIZE`) | не менее (размер группы + 3) x размер блока; округляется вниз до кратного размеру блока |
| Тома читаемого saveset-а | до 9999; поиск прекращается после 16 отсутствующих имён подряд |
| Входные спецификации | 64 |
| Шаблоны `/SELECT`, `/EXCLUDE` | по 64 |
| Глубина обхода каталогов | 256 уровней |
| Спецификация файла | 4095 байт |
| Текст `/COMMENT` | 255 байт |
| Командная строка в сводке | 4096 байт |
| Пароль | от 1 до 1024 байт |
| Итерации PBKDF2 | не менее 1000 (по умолчанию 600000) |
| Данные в одной записи DATA или DATAZ | 1048576 байт |

#### Прочие ограничения

- Saveset, записываемый на стандартный вывод, -- один том.
- Saveset со стандартного ввода читается один раз и только вперёд: поиска
  по каталогу нет; vbkx отвергает для него имена.
- `/PHYSICAL` и `/IMAGE` принимают один вход при сохранении и один saveset
  при восстановлении.
- `/INCREMENTAL` отвергает saveset без каталога и saveset, созданный до
  X01-02 (NOTINCR).
- `/ORIGINAL` требует saveset, созданный X01-02 или позднее (ORIGNOBASE); с
  `/INCREMENTAL` -- saveset с одной базой.
- `/IMAGE` восстанавливает только файловые системы типов ext2, ext3, ext4,
  xfs, btrfs, vfat и msdos.
- Saveset-ы никогда не изменяются на месте; в существующий saveset нельзя ни
  добавить, ни удалить из него что-либо.

### /BEFORE

Квалификатор выбора входных файлов.

**Формат**

`/BEFORE=time`

**Описание**

Выбирает для сохранения только файлы, время которых раньше заданного.
Рассматривается время изменения, если не задан `/CREATED` или `/CHANGED`.
Каталоги сохраняются всегда.

Время записывается так (допускается однозначное сокращение ключевого
слова):

| Форма | Смысл |
|---|---|
| `dd-MMM-yyyy[ hh:mm[:ss]]` | Абсолютное время, например `3-OCT-2026 14:00` |
| `hh:mm[:ss]` | Сегодня в это время |
| `-[dd ]hh:mm[:ss]` | Интервал назад от текущего момента: `"-1 0:0"` -- сутки назад |
| `TODAY`, `YESTERDAY`, `TOMORROW` | Полночь в начале этого дня |
| `NOW` | Текущий момент |

`/BEFORE` делает saveset инкрементным: файлы, которые он не выбрал,
перечисляются в каталоге как PRESENT (см. раздел 1.5). О неправильно
записанном времени сообщается IVTIME. `/BEFORE` нельзя сочетать с `/PHYSICAL`
и `/DELETE`. При копировании копируются только выбранные файлы.

**Пример**

```
$ vbackup /home/rrl old.bck "/BEFORE=1-JAN-2026"
```

Сохраняются файлы `/home/rrl`, в последний раз изменённые до 1 января
2026 г.; более новые файлы перечисляются в каталоге как присутствующие.

---

### /BLOCK_SIZE

Квалификатор выходного saveset-а.

**Формат**

`/BLOCK_SIZE=n`

**Описание**

Задаёт размер блоков saveset-а в байтах. *n* должно быть кратно 512 и
лежать в пределах от 8192 до 1048576; по умолчанию 65536. Большие блоки
немного быстрее; маленькие теряют меньше данных при потере одного блока.
Размер блока читаемого saveset-а берётся из самого saveset-а.

О недопустимом значении сообщается IVQUAL.

**Пример**

```
$ vbackup /home home.bck /BLOCK_SIZE=1000
%VBACKUP-E-IVQUAL, Value: 1000, Qualifier: /BLOCK_SIZE - is not valid
$ vbackup /home home.bck /BLOCK_SIZE=262144
```

### /BRIEF

Квалификатор листинга.

**Формат**

`/BRIEF`

**Описание**

С `/LIST` выводит для каждого файла хранимое имя, размер и дату изменения;
имена каталогов оканчиваются косой чертой. Это умолчание. `/BRIEF` и `/FULL`
нельзя задавать вместе (CONFQUAL).

**Пример**

```
$ vbackup rrl.bck /LIST /BRIEF

Written with:      VBACKUP X01-08

rrl/link                                                  5   5-OCT-2026 14:19
rrl/sub/

rrl/sub/c.h                                               2   5-OCT-2026 14:19

Total of 6 files, 108902 bytes

### /BY_OWNER

Квалификатор выбора входных файлов.

**Формат**

`/BY_OWNER=user`

**Описание**

Выбирает только файлы заданного пользователя -- по имени или по числовому
идентификатору. Каталоги берутся всегда. Файлы других владельцев не
охватываются: они не сохраняются и не перечисляются как присутствующие. О
неизвестном имени, не являющемся числом, сообщается IVQUAL. `/BY_OWNER`
нельзя сочетать с `/PHYSICAL` и `/IMAGE`.

**Пример**

```
# vbackup /home ivan.bck /BY_OWNER=ivan
```

---

### /CHANGED

Квалификатор выбора входных файлов.

**Формат**

`/CHANGED`

**Описание**

Заставляет `/SINCE` и `/BEFORE` рассматривать время смены атрибутов (ctime)
файла. Это время меняется также при изменении прав, владельца или имени
файла. Задать можно только один из `/MODIFIED`, `/CREATED` и `/CHANGED`
(CONFQUAL).

**Пример**

```
$ vbackup /etc etc.bck /SINCE=YESTERDAY /CHANGED
```

---

### /COMMENT

Квалификатор выходного saveset-а.

**Формат**

`/COMMENT="text"`

**Описание**

Сохраняет текст длиной не более 255 байт в сводке saveset-а. `/LIST`
выводит его в строке `Comment:`.

**Пример**

```
$ vbackup /home/rrl rrl.bck /COMMENT="before the upgrade"
```

---

### /COMPARE

Квалификатор команды.

**Формат**

`input-specifier [output-specifier] /COMPARE`

**Описание**

Читает saveset и сравнивает каждый файл с диском: тип, размер, содержимое
и цель символической ссылки. Владельцы, режимы и времена не сравниваются.
С выходным параметром файлы ищутся в этом каталоге по хранимым именам; без
него -- в базах, записанных в saveset-е (там, откуда они были сохранены).
Первое различие каждого файла сообщается COMPARERR, итоги -- CMPSUMM. Любое
различие даёт код завершения 2.

`/SELECT` и `/EXCLUDE` ограничивают сравнение. Saveset может быть `-`. Вход
должен быть ровно одним saveset-ом (иначе NOTSAVESET).

**Пример**

```
$ vbackup rrl.bck /COMPARE
%VBACKUP-I-STARTED, Operation: compare, Input: rrl.bck - started
%VBACKUP-E-COMPARERR, File: /home/rrl/a.txt - the size differs
%VBACKUP-I-CMPSUMM, Files: 6, Differences: 1 - compared
%VBACKUP-I-COMPLETED, Operation: compare, Seconds: 0.00 - completed with errors
```

---

### /CONFIRM

Квалификатор команды.

**Формат**

`/CONFIRM`
`/NOCONFIRM` (по умолчанию)

**Описание**

Спрашивает на терминале перед обработкой каждого файла:

| Операция | Вопрос |
|---|---|
| Сохранение | `Save` *хранимое-имя* `? [N]:` |
| Восстановление, копирование | `Restore` *файл* `? [N]:` |
| `/DELETE`, удаления `/INCREMENTAL` | `Delete` *файл* `? [N]:` |

Ответ -- `YES`, `NO`, `QUIT` или `ALL`; достаточно первой буквы, пустой ответ
означает `NO`. `ALL` обрабатывает остальное без вопросов. `QUIT` прекращает
операцию; прерванное так сохранение всё же правильно закрывает saveset. Без
терминала ответом считается `QUIT`. `/CONFIRM` отвергается при
восстановлении `/IMAGE` (CONFQUAL).

**Пример**

```
$ vbackup /home/rrl rrl.bck /CONFIRM
Save rrl/a.txt ? [N]: Y
Save rrl/core ? [N]: N
Save rrl/sub/b.c ? [N]: ALL
```

---

### /CREATED

Квалификатор выбора входных файлов.

**Формат**

`/CREATED`

**Описание**

Заставляет `/SINCE` и `/BEFORE` рассматривать время создания (рождения)
файла. Linux хранит его на ext4, xfs и btrfs. В файловой системе без него
времени создания нет, и её файлы не выбираются ни `/SINCE`, ни `/BEFORE`.
Задать можно только один из `/MODIFIED`, `/CREATED` и `/CHANGED`.

**Пример**

```
$ vbackup /data new.bck /SINCE=TODAY /CREATED
```

---

### /CROSS_DEVICE

Квалификатор выбора входных файлов.

**Формат**

`/CROSS_DEVICE`
`/NOCROSS_DEVICE` (по умолчанию)

**Описание**

По умолчанию встреченная при обходе точка монтирования сохраняется как
каталог, но смонтированное на ней -- нет; поэтому сохранение `/` не
сохраняет `/proc`, `/sys` или смонтированный USB-диск. `/CROSS_DEVICE`
заходит и в другие файловые системы. Сохранение `/IMAGE` всегда работает как
`/NOCROSS_DEVICE`.

**Пример**

```
# vbackup / root.bck /NOCROSS_DEVICE '/EXCLUDE=(tmp,var/tmp)'
```

---

### /DATA_FORMAT

Квалификатор выходного saveset-а.

**Формат**

`/DATA_FORMAT=COMPRESSED`
`/DATA_FORMAT=UNCOMPRESSED` (по умолчанию)

**Описание**

`COMPRESSED` хранит данные файлов сжатыми в блочном формате LZ4 (записи
DATAZ); несжимаемые данные хранятся как есть. Сводка отмечает это, и `/LIST`
выводит `Data format: compressed (LZ4)`. Сжатие выполняется в нескольких
потоках (`VBACKUP_ZTHREADS`); saveset от их числа не зависит. Читающие
распознают сжатые данные сами. `/DATA_FORMAT` работает и с `/PHYSICAL`, и с
`/IMAGE`. См. раздел 1.7.

**Пример**

```
$ vbackup /home /mnt/usb/home.bck /DATA_FORMAT=COMPRESSED
```

---

### /DELETE

Квалификатор входного файла.

**Формат**

`/DELETE`

**Описание**

После сохранения удаляет с диска файлы, которые были сохранены и
проверены. Требуется `/VERIFY` (иначе QUALUSE). Файл удаляется, только если
проверка не нашла вообще никаких различий во всём saveset-е и файл не
изменился с момента сохранения: тот же inode и устройство, а для всего,
кроме дополнительного имени жёсткой ссылки, -- тот же размер, время
изменения и время смены атрибутов, что в его элементе каталога. Иначе файл
остаётся, и SRCKEPT сообщает почему. Удаляются только обычные файлы,
символические и жёсткие ссылки в состоянии OK; каталоги остаются.

`/CONFIRM` спрашивает перед каждым удалением; `/LOG` сообщает о каждом
(SRCDELETED); DELSUMM даёт итоги. `/DELETE` нельзя сочетать с `/PHYSICAL`,
`/IMAGE`, `/SINCE` и `/BEFORE` (CONFQUAL). Если saveset идёт на стандартный
вывод, его нельзя проверить, и ничего не удаляется.

**Пример**

```
$ vbackup /home/ivan/old /mnt/usb/old.bck /VERIFY /DELETE /LOG
...
%VBACKUP-I-CMPSUMM, Files: 3, Differences: 0 - compared
%VBACKUP-I-SRCDELETED, File: /home/ivan/old/x - deleted: it is in the saveset and verified
%VBACKUP-I-SRCDELETED, File: /home/ivan/old/y - deleted: it is in the saveset and verified
%VBACKUP-I-DELSUMM, Deleted: 2, Kept: 0
```

### /ENCRYPT

Квалификатор выходного saveset-а.

**Формат**

`/ENCRYPT`

**Описание**

Создаёт зашифрованный saveset (см. раздел 1.8). Пароль читается из файла
ключа `/KEY_FILE` или `VBACKUP_KEY_FILE`; иначе он дважды запрашивается на
терминале без эха. Без файла ключа и терминала сохранение завершается с
NOKEY; при несовпадении ответов -- с KEYMATCH. С `/LOG` сообщение ENCRYPTED
показывает число итераций.

`/ENCRYPT` задаётся только при сохранении. Зашифрованный saveset при чтении
распознаётся сам: восстановление, `/LIST`, `/COMPARE`, `/EXTRACT` и
перестройка журнала запрашивают пароль или берут `/KEY_FILE`. `/ENCRYPT`,
заданный другой операции, отвергается (QUALUSE).

**Пример**

```
$ vbackup /home/me me.bck /ENCRYPT
Passphrase for me.bck:
The same passphrase again:
```

---

### /EXCLUDE

Квалификатор выбора входных файлов.

**Формат**

`/EXCLUDE=(pattern[,...])`

**Описание**

Исключает файлы, хранимое имя которых соответствует одному из шаблонов.
Подходящий каталог исключается со всем содержимым. В шаблоне `*`
соответствует любым символам, включая `/`, а `%` и `?` -- одному символу. Не
более 64 шаблонов (TOOMANY).

При сохранении и копировании исключённые файлы не охватываются; при
восстановлении и сравнении они пропускаются. Листинг saveset-а `/EXCLUDE` не
ограничивает. Его нельзя сочетать с `/INCREMENTAL`, `/PHYSICAL` и `/IMAGE`.

**Пример**

```
$ vbackup /home/rrl rrl.bck '/EXCLUDE=(*.o,*/.cache)'
```

### /EXTRACT

Квалификатор команды.

**Формат**

`input-specifier [output-specifier] /EXTRACT=stored-name`

**Описание**

Записывает содержимое одного обычного файла saveset-а в выходной файл или
на стандартный вывод, если выход не задан или равен `-`. Имя точное, без
шаблонов, как его показывает `/LIST`. Файл находится через каталог, поэтому
это быстро даже в очень большом saveset-е; из канала или saveset-а без
каталога он ищется чтением. Данные проверяются по CRC файла (CRCERR).

Имя, которого нет в saveset-е, даёт NOTFOUND; файл, не являющийся обычным,
-- UNSUPP. Существующий выходной файл сохраняется (FILEEXISTS), если не задан
`/REPLACE`.

**Пример**

```
$ vbackup home.bck /EXTRACT=rrl/notes.txt | less
$ vbackup home.bck /tmp/notes.txt /EXTRACT=rrl/notes.txt
```

### /FORMAT

Квалификатор листинга.

**Формат**

`/FORMAT=VMS` (по умолчанию)
`/FORMAT=LS`

**Описание**

`VMS` -- листинг, описанный в `/BRIEF` и `/FULL`. `LS` выводит без сводки по
одной строке на файл, как `ls -l`: режим, число ссылок, владелец, группа,
размер, дата и время (`mm-dd-yyyy hh:mm:ss`), полное хранимое имя и для
символической ссылки `-> цель`. Он предназначен для программ; его читает
модуль Midnight Commander.

**Пример**

```
$ vbackup rrl.bck /LIST /FORMAT=LS
drwxr-xr-x   3 root     root           4096 10-05-2026 14:19:25 rrl
-rw-r--r--   1 root     root              6 10-05-2026 14:19:25 rrl/a.txt
lrwxrwxrwx   1 root     root              5 10-05-2026 14:19:25 rrl/link -> a.txt
drwxr-xr-x   2 root     root           4096 10-05-2026 14:19:25 rrl/sub
-rw-r--r--   1 root     root         108894 10-05-2026 14:19:25 rrl/sub/b.c
-rw-r--r--   1 root     root              2 10-05-2026 14:19:25 rrl/sub/c.h
```

### /FULL

Квалификатор листинга.

**Формат**

`/FULL`

**Описание**

С `/LIST` выводит для каждого файла тип, размер, владельца (имя и номер),
защиту, время изменения, контрольную сумму и состояние, а также цель
ссылки. Типы: `file`, `directory`, `symlink`, `hard link`, `character
device`, `block device`, `FIFO` и `socket`; состояния: `OK`, `changed while
saved` и `read error`.

С `/JOURNAL /LIST` добавляет известные журналу файлы -- для каждого размер,
время записи и saveset с его последней копией.

**Пример**

```
$ vbackup rrl.bck /LIST /FULL
...
rrl/a.txt
    Type: file         Size: 6              Owner: root:root (0,0)  Protection: -rw-r--r--
    Modified:  5-OCT-2026 14:19:25.00  Checksum: 363A3020  Status: OK
rrl/link
    Type: symlink      Size: 5              Owner: root:root (0,0)  Protection: lrwxrwxrwx
    Modified:  5-OCT-2026 14:19:25.00  Checksum: 00000000  Status: OK
    Link to: a.txt
...
```

### /GROUP_SIZE

Квалификатор выходного saveset-а.

**Формат**

`/GROUP_SIZE=n`

**Описание**

Задаёт число блоков данных, после которых пишется блок XOR. *n* -- от 0 до
100; по умолчанию 10, что увеличивает saveset примерно на 10%. Один плохой
блок в группе восстанавливается при чтении saveset-а (BLKFIXED). Меньшее *n*
чинит больше повреждений и стоит больше места. `/GROUP_SIZE=0` не пишет
блоков XOR, и ничего нельзя починить.

**Пример**

```
$ vbackup /home /mnt/usb/home.bck /GROUP_SIZE=4
```

### /HELP

Квалификатор команды.

**Формат**

`/HELP [topic ...]`

**Описание**

Выводит описание VBACKUP из библиотеки справки или описание заданной темы.
Каждое слово после `/HELP` -- часть темы, в том числе квалификатор: `vbackup
/HELP /VERIFY`. Среди тем -- квалификаторы, PARAMETERS, WILDCARDS,
INCREMENTAL, TIME, PLUGINS, VBKX, EXAMPLES, TROUBLESHOOTING и MESSAGES. О
несуществующей теме сообщается NOTOPIC. `-h` равносильно `/HELP`. Если VBACKUP
собран без пакета HELP, вместо этого выводится краткая справка по
использованию.

Библиотека ищется в файле, названном `VBACKUP_HELPLIB`, затем в
`../share/help/vbackup.hlb` относительно образа программы, рядом с образом и
там, куда продукт был установлен.

**Пример**

```
$ vbackup /HELP /VERIFY

  VBACKUP /VERIFY

    After the saveset is written, VBACKUP reads it again and compares
    every file with the disk. A difference is reported with
    %VBACKUP-E-COMPARERR.
```

### /IGNORE

Квалификатор выбора входных файлов.

**Формат**

`/IGNORE=NOBACKUP`

**Описание**

Файлы и каталоги с флагом nodump (`chattr +d`) обычно не сохраняются; это
флаг NOBACKUP системы OpenVMS. С `/LOG` о каждом сообщается (SKIPPED).
`/IGNORE=NOBACKUP` сохраняет и их. Сохранение `/IMAGE` всегда игнорирует этот
флаг.

**Пример**

```
$ vbackup /home/rrl rrl.bck /IGNORE=NOBACKUP
```

### /IMAGE

Квалификатор команды.

**Формат**

`mount-point|device saveset /IMAGE`
`saveset device /IMAGE /REPLACE`

**Описание**

При сохранении сохраняет каждый файл одной целой файловой системы и её
идентичность (см. раздел 1.6). Вход -- одна точка монтирования или одно
смонтированное блочное устройство; подкаталог -- не том (IMGNOTVOL),
несмонтированное устройство отвергается (IMGNOTMNT). Если UUID файловой
системы найти не удалось, сообщается IMGNOID, и новая файловая система
получит новый UUID.

При восстановлении создаёт на выходном устройстве новую файловую систему
сохранённого типа, с той же меткой и UUID, и восстанавливает в неё файлы.
Требует `/REPLACE` и отвергает смонтированное или занятое устройство
(PHYSMOUNTED, PHYSHELD), устройство, которое не вместит файлы (IMGSMALL), и
тип, который VBACKUP не умеет создавать (IMGUNSUPP). На терминале VBACKUP
спрашивает:

```
Everything on device (n bytes) is to be overwritten with the device saved in saveset.
Type YES to go on:
```

Любой ответ, кроме `YES`, оставляет устройство нетронутым (PHYSABORT). Если
стандартный ввод -- не терминал, ничего не спрашивается. `/LOG` сообщает
команду mkfs (IMGCMD). Итоги сообщает IMGSUMM.

`/IMAGE` работает с `/RECORD`, `/SINCE`, `/VERIFY`, `/DATA_FORMAT` и `/ENCRYPT`;
отвергает `/SELECT`, `/EXCLUDE`, `/BY_OWNER`, `/INCREMENTAL`, `/PHYSICAL`,
`/ORIGINAL`, `/DELETE` и при восстановлении `/CONFIRM`. Сохранение `/IMAGE`
принимает один вход, восстановление -- один saveset (QUALUSE).

**Пример**

```
# vbackup /mnt/data /mnt/usb/data.bck /IMAGE
# vbackup /mnt/usb/data.bck /dev/sdc1 /IMAGE /REPLACE
```

### /INCREMENTAL

Квалификатор выходного файла.

**Формат**

`full-saveset,incremental-saveset[,...] directory /INCREMENTAL`

**Описание**

Восстанавливает цепочку saveset-ов: полный saveset, затем каждый
инкрементный, от старейшего к новейшему, и приводит каждый каталог
saveset-ов к виду, который он имел при последнем сохранении. Прежде чем
трогать файлы очередного saveset-а, читается его каталог; после
восстановления saveset-а файл, находящийся в каталоге saveset-а, но не
перечисленный в его каталоге, удаляется (DELETED). О файле, который каталог
перечисляет как присутствующий, но который не принёс ни один предыдущий
saveset, сообщается (MISSING). `/INCREMENTAL` подразумевает `/REPLACE`.

Очищаются только каталоги, которые есть в saveset-е, и никогда -- сам
выходной каталог. Saveset без каталога, с испорченным каталогом или
созданный до X01-02 отвергается (NOTINCR), и на нём цепочка обрывается:
ничего не удаляется на основании неполного списка. `/CONFIRM` спрашивает
перед каждым удалением, `/LOG` сообщает о нём. `/SELECT` и `/EXCLUDE` нельзя
задавать с `/INCREMENTAL` (CONFQUAL), как и `/PHYSICAL` и `/IMAGE`. С
`/ORIGINAL` saveset должен иметь одну базу.

**Пример**

```
$ vbackup full.bck,mon.bck,tue.bck /home /INCREMENTAL
```

### /JOURNAL

Квалификатор команды.

**Формат**

`/JOURNAL[=file]`

**Описание**

Задаёт журнал, используемый `/RECORD` и `/SINCE=BACKUP`. По умолчанию это
`/var/lib/vbackup/vbackup.jnl` для root и `$HOME/.vbackup/vbackup.jnl` для
остальных пользователей; каталог при необходимости создаётся. Обычное
применение -- отдельный журнал для каждого плана резервного копирования.

С `/LIST` и без параметров выводится листинг журнала: известные ему
saveset-ы, для каждого -- время, вид, число файлов и байтов, имя и фильтр.
`/FULL` добавляет файлы; `/SELECT` выбирает файлы по их абсолютным именам. О
журнале, который не удаётся прочитать или записать, сообщается JNLERR.

**Пример**

```
$ vbackup /JOURNAL=/backup/plan1.jnl /LIST
Journal:           /backup/plan1.jnl

 5-OCT-2026 14:20:37.00  full               7 files        3108910 bytes  /backup/full.bck
 5-OCT-2026 14:20:38.00  incremental        3 files              4 bytes  /backup/mon.bck /SINCE=BACKUP

Total of 2 savesets, 6 files recorded
```

### /KEY_FILE

Квалификатор команды.

**Формат**

`/KEY_FILE=file`

**Описание**

Задаёт файл ключа с паролем зашифрованного saveset-а: его первую строку без
признака конца строки. Файл должен быть обычным файлом, читать и изменять
который может только владелец (`chmod 600`); иначе он отвергается (KEYFILE).
Без `/KEY_FILE` используется файл, названный `VBACKUP_KEY_FILE`; без того и
другого пароль запрашивается на терминале. `/KEY_FILE` служит сохранению
`/ENCRYPT` и любому чтению зашифрованного saveset-а; для незашифрованного
saveset-а он ни на что не влияет.

**Пример**

```
$ chmod 600 /root/backup.key
# vbackup /home /backup/home.bck /ENCRYPT /KEY_FILE=/root/backup.key
```

### /LIST

Квалификатор команды.

**Формат**

`/LIST[=file]`

**Описание**

Выводит сводку saveset-а -- имя, число томов, продукт, узел, пользователя,
команду, дату, базы, вид и фильтр, размеры блока, группы и тома, формат
данных, комментарий, шифрование, а для saveset-ов `/PHYSICAL` и `/IMAGE` --
устройство или файловую систему, -- а затем его файлы в форме, выбранной
`/BRIEF`, `/FULL` или `/FORMAT`. Файлы читаются из каталога; без каталога
(NOTRAILER) читается весь saveset (NOCATALOG). Присутствующие (PRESENT)
элементы инкрементного saveset-а не выводятся. С именем файла листинг
пишется в этот файл; существующий файл перезаписывается.

Заданный при сохранении, `/LIST` выводит листинг нового saveset-а (кроме
случая, когда тот идёт на стандартный вывод). С `/JOURNAL` и без параметров
выводит листинг журнала. Листинг saveset-а `/SELECT` и `/EXCLUDE` не
ограничивают.

**Пример**

```
$ vbackup /backup/rrl.bck /LIST=/tmp/rrl.lis /FULL
```

### /LOG

Квалификатор команды.

**Формат**

`/LOG`
`/NOLOG` (по умолчанию)

**Описание**

Сообщает о каждом сохранённом (SAVED), восстановленном (RESTORED),
сравнённом (COMPARED), скопированном (COPIED) или удалённом (SRCDELETED,
DELETED) файле, о каждом созданном томе (CREATED; без `/LOG` -- только о томах
со второго), о файлах, пропущенных из-за флага nodump (SKIPPED), о шифровании
(ENCRYPTED) и о команде mkfs (IMGCMD). Без `/LOG` VBACKUP сообщает о начале,
итогах и завершении операции.

**Пример**

```
$ vbackup rrl.bck /tmp/out /LOG
%VBACKUP-I-STARTED, Operation: restore, Input: rrl.bck, Output: /tmp/out - started
%VBACKUP-I-RESTORED, File: /tmp/out/rrl - restored
%VBACKUP-I-RESTORED, File: /tmp/out/rrl/a.txt - restored
...
%VBACKUP-I-RESTSUMM, Files: 6, Bytes: 108902 - restored
%VBACKUP-I-COMPLETED, Operation: restore, Seconds: 0.00 - completed
```

### /MODIFIED

Квалификатор выбора входных файлов.

**Формат**

`/MODIFIED`

**Описание**

Заставляет `/SINCE` и `/BEFORE` рассматривать время изменения (mtime) файла.
Это умолчание. Задать можно только один из `/MODIFIED`, `/CREATED` и
`/CHANGED`.

**Пример**

```
$ vbackup /home home.bck /SINCE=TODAY /MODIFIED
```

### /ORIGINAL

Квалификатор выходного файла.

**Формат**

`saveset /ORIGINAL`

**Описание**

Восстанавливает каждый файл в каталог, из которого он был сохранён;
выходной параметр не задаётся (иначе QUALUSE). Места -- абсолютные базы,
записываемые в сводку начиная с X01-02; saveset, созданный раньше, их не
знает (ORIGNOBASE). Перед записью VBACKUP сообщает, куда пойдут файлы
(ORIGTARGET). Saveset из нескольких входных спецификаций возвращает каждый
файл под его собственную базу. Существующие файлы сохраняются, если не
задан `/REPLACE`. `/ORIGINAL` нельзя сочетать с `/PHYSICAL` и `/IMAGE`; с
`/INCREMENTAL` saveset должен иметь одну базу.

Осторожно с saveset-ами, созданными не вами: `/ORIGINAL` пишет туда, куда
указывает saveset.

**Пример**

```
# vbackup /mnt/usb/home.bck /ORIGINAL /REPLACE
```

### /OWNER

Квалификатор выходного файла.

**Формат**

`/OWNER=ORIGINAL`
`/OWNER=DEFAULT`
`/OWNER=user`

**Описание**

Задаёт владельца восстановленных или скопированных файлов.

| Вариант | Смысл |
|---|---|
| `ORIGINAL` | Сохранённые владелец и группа: по имени, если имя известно в этой системе, иначе по номеру. Умолчание для root. |
| `DEFAULT` | Файлы принадлежат пользователю, запустившему VBACKUP. Умолчание для остальных пользователей, которые всё равно не могут отдавать файлы. |
| *user* | Все файлы принадлежат этому пользователю и его основной группе. |

`ORIGINAL` и `DEFAULT` можно сокращать. О неизвестном пользователе
сообщается IVQUAL; о владельце, которого не удалось установить, -- ATTRERR.

**Пример**

```
# vbackup /backup/rrl.bck /home /OWNER=rrl
```

### /PHYSICAL

Квалификатор команды.

**Формат**

`device|image-file saveset /PHYSICAL`
`saveset device|image-file /PHYSICAL [/REPLACE]`

**Описание**

При сохранении поблочно копирует одно блочное устройство или файл образа
(см. раздел 1.6). Вход должен быть блочным устройством или обычным файлом
(PHYSNOTDEV). Устройство, смонтированное на чтение и запись, или раздел
которого смонтирован так, отвергается (PHYSMOUNTED); так же -- занятое
устройство (PHYSHELD). Если устройство меняет размер во время чтения,
сообщается PHYSSIZE. Итоги сообщает PHYSSUMM.

При восстановлении saveset должен быть создан с `/PHYSICAL` (PHYSNOTPHYS). На
блочное устройство требуется `/REPLACE` (PHYSREPLACE); смонтированное
(PHYSMOUNTED), занятое (PHYSHELD) устройство и устройство меньше
сохранённого (PHYSSMALL) отвергаются; на терминале спрашивается `YES`, как
для `/IMAGE` (PHYSABORT). На устройство большего размера сообщается
PHYSLARGER. Новый файл образа создаётся; существующий перезаписывается
только с `/REPLACE`. Потерянный блок saveset-а -- потерянная часть устройства
(FILDAMAGED). После восстановления на устройство PHYSUUID напоминает, что
копия несёт UUID оригинала.

`/PHYSICAL` принимает один вход при сохранении и один saveset при
восстановлении. Отвергает `/SELECT`, `/EXCLUDE`, `/SINCE`, `/BEFORE`,
`/BY_OWNER`, `/RECORD`, `/INCREMENTAL`, `/IMAGE`, `/ORIGINAL` и `/DELETE`.
`/DATA_FORMAT=COMPRESSED` и `/ENCRYPT` работают с ним.

**Пример**

```
# vbackup /dev/sdb1 /mnt/usb/sdb1.bck /PHYSICAL
# vbackup /mnt/usb/sdb1.bck /dev/sdc1 /PHYSICAL /REPLACE
```

### /RECORD

Квалификатор команды.

**Формат**

`/RECORD`
`/NORECORD` (по умолчанию)

**Описание**

При сохранении записывает saveset в журнал после того, как он записан и,
при `/VERIFY`, проверен без различий; а для каждого файла, сохранённого в
состоянии OK, -- его абсолютное имя, inode, размер, время изменения и время
смены атрибутов (RECORDED). Файл, изменившийся во время сохранения или не
прочитанный, не записывается, поэтому следующее `/SINCE=BACKUP` сохранит его
снова. Saveset, записанный в `-`, записывается как `(standard output)`.

С saveset-ами и без выходного параметра перестраивает журнал по их
каталогам: каждый элемент в состоянии OK с данными inode (X01-02 и
позднее) даёт состояние файла, более поздний saveset побеждает. Saveset без
TRAILER пропускается (NOTRAILER); элементы без данных inode подсчитываются
(NOINODE).

`/RECORD` нельзя сочетать с `/PHYSICAL`.

**Пример**

```
$ vbackup /home full.bck /RECORD /JOURNAL=/backup/home.jnl
$ vbackup full.bck,mon.bck /RECORD /JOURNAL=/backup/home.jnl
%VBACKUP-I-STARTED, Operation: rebuild of the journal, Input: full.bck - started
%VBACKUP-I-RECORDED, Files: 6, Journal: /backup/home.jnl - recorded
%VBACKUP-I-COMPLETED, Operation: rebuild of the journal, Seconds: 0.00 - completed
```

---

### /REPLACE

Квалификатор выходного файла; квалификатор выходного saveset-а.

**Формат**

`/REPLACE`
`/NOREPLACE` (по умолчанию)

**Описание**

| Операция | Действие |
|---|---|
| Сохранение | Существующий saveset перезаписывается. Без `/REPLACE` сохранение останавливается с OPENOUT (errno 17, File exists). |
| Восстановление, копирование | Существующий файл удаляется и восстанавливается заново. Без `/REPLACE` он сохраняется, и сообщается FILEEXISTS. |
| Извлечение | Существующий выходной файл перезаписывается. |
| Восстановление `/PHYSICAL`, `/IMAGE` | Выходное устройство перезаписывается; обязателен. |

`/INCREMENTAL` подразумевает `/REPLACE`.

**Пример**

```
$ vbackup /backup/rrl.bck /home '/SELECT=*.c' /REPLACE
```

---

### /SAVE_SET

Квалификатор выходного saveset-а.

**Формат**

`/SAVE_SET`

**Описание**

Указывает, что выходной параметр -- saveset, каким бы ни было его имя. Не
нужен, если имя оканчивается на `.bck` или `.sav` или равно `-`. Без него
выход с другим именем при входе, не являющемся saveset-ом, означает
копирование. На входной стороне `/SAVE_SET` ни на что не влияет: saveset
распознаётся по содержимому.

**Пример**

```
$ vbackup /etc /backup/etc.2026-10-05 /SAVE_SET
```

---

### /SELECT

Квалификатор выбора входных файлов.

**Формат**

`/SELECT=(pattern[,...])`

**Описание**

Берёт только файлы, хранимое имя которых соответствует одному из шаблонов.
В шаблоне `*` соответствует любым символам, включая `/`, а `%` и `?` -- одному
символу. Хранимое имя задаётся относительно базы, например `rrl/src/a.c`;
хранимые имена показывает `/LIST`. Не более 64 шаблонов.

При сохранении и копировании шаблоны выбирают файлы; каталоги берутся
всегда. При восстановлении каталог восстанавливается, только если он сам
соответствует шаблону (родительские каталоги выбранного файла создаются в
любом случае); при сравнении несоответствующие файлы пропускаются. С
`/JOURNAL /LIST /FULL` шаблоны сопоставляются с абсолютными именами журнала.
Листинг saveset-а `/SELECT` не ограничивает. Его нельзя сочетать с
`/INCREMENTAL`, `/PHYSICAL` и `/IMAGE`.

**Пример**

```
$ vbackup home.bck /tmp/r '/SELECT=(*.c,*.h)'
```

---

### /SINCE

Квалификатор выбора входных файлов.

**Формат**

`/SINCE=time`
`/SINCE=BACKUP`

**Описание**

Выбирает для сохранения только файлы, время которых не раньше заданного
(формы записи времени см. в `/BEFORE`). Рассматривается время изменения,
если не задан `/CREATED` или `/CHANGED`. Каталоги сохраняются всегда.

`/SINCE=BACKUP` выбирает файлы, изменившиеся с момента их последнего
сохранения с `/RECORD`, как это знает журнал (раздел 1.5). Файл, неизвестный
журналу, сохраняется. Без журнала сохраняется всё, как в первый раз, и
сообщается NOJOURNAL.

Любой `/SINCE` делает saveset инкрементным; сводка хранит фильтр в том виде,
в каком он задан (`Filter:` в листинге), а INCRSUMM подсчитывает файлы,
перечисленные как присутствующие. `/SINCE` нельзя сочетать с `/PHYSICAL` и
`/DELETE`.

**Пример**

```
$ vbackup /home /mnt/usb/home.bck /SINCE=TODAY /VOLUME_SIZE=4G
$ vbackup /home mon.bck /SINCE=BACKUP /RECORD
```

---

### /VERIFY

Квалификатор команды.

**Формат**

`/VERIFY`
`/NOVERIFY` (по умолчанию)

**Описание**

При сохранении, после записи saveset-а, читает его обратно и сравнивает
каждый файл с диском (VERIFYING, затем COMPARERR при различии и CMPSUMM с
итогами). Saveset, записанный на стандартный вывод, не проверяется. `/DELETE`
и, при `/VERIFY`, `/RECORD` действуют, только если проверка не нашла
различий.

При копировании читает каждый обычный файл обратно с обеих сторон сразу
после копирования и сравнивает их; о различии сообщается COMPARERR, а
CMPSUMM даёт итоги, если различия найдены.

**Пример**

```
$ vbackup /home/rrl /backup/rrl.bck /VERIFY
%VBACKUP-I-STARTED, Operation: save, Input: /home/rrl, Output: /backup/rrl.bck - started
%VBACKUP-I-SAVESUMM, Files: 6, Bytes: 108902, Blocks: 5, Volumes: 1 - saved
%VBACKUP-I-VERIFYING, Saveset: /backup/rrl.bck - verifying
%VBACKUP-I-CMPSUMM, Files: 6, Differences: 0 - compared
%VBACKUP-I-COMPLETED, Operation: save, Seconds: 0.00 - completed
```

---

### /VOLUME_SIZE

Квалификатор выходного saveset-а.

**Формат**

`/VOLUME_SIZE=size`

**Описание**

Разрезает saveset на тома заданного размера в байтах, за которым может
следовать K, M, G или T (двоичные множители) и необязательная B. Размер
округляется вниз до кратного размеру блока и должен быть не меньше
(размер группы + 3) x размер блока: 851968 байт при умолчаниях. Тома
называются *имя*, *имя*`.002`, *имя*`.003` и так далее (раздел 1.3); о каждом
томе после первого сообщается (CREATED). Храните тома вместе в одном
каталоге.

`/VOLUME_SIZE` отвергается для saveset-а, записываемого на стандартный вывод
(QUALUSE).

**Пример**

```
$ vbackup /home home.bck /VOLUME_SIZE=4G
$ vbackup /home home.bck /VOLUME_SIZE=100K
%VBACKUP-E-IVQUAL, Value: 100K, Qualifier: /VOLUME_SIZE - is not valid
```

---

### /XATTRS

Квалификатор входного файла; квалификатор выходного файла.

**Формат**

`/XATTRS` (по умолчанию)
`/NOXATTRS`

**Описание**

Сохраняет, восстанавливает и копирует расширенные атрибуты файлов:
пользовательские атрибуты, списки POSIX ACL (`system.posix_acl_access`,
`system.posix_acl_default`), возможности файлов и метку SELinux. Некоторые из
них может восстановить только root; о тех, что не удалось установить,
сообщается ATTRERR. `/NOXATTRS` их не сохраняет и не восстанавливает.

**Пример**

```
$ vbackup /home/rrl rrl.bck /NOXATTRS
```

### Переменные окружения

На VBACKUP влияют следующие переменные окружения. Переменные с пометкой
*vbkx* учитывает и vbkx; с пометкой *распаковщики* -- vbkx-go, vbkx-rs и
vbkx-pl.

| Переменная | Смысл |
|---|---|
| `VBACKUP_KEY_FILE` | Файл ключа зашифрованного saveset-а, если не задан `/KEY_FILE` (*vbkx*, *распаковщики*, модули). |
| `VBACKUP_NOPROMPT` | `1` -- никогда не спрашивать пароль на терминале; без файла ключа результат -- NOKEY. Устанавливается модулями файловых менеджеров (*vbkx*). |
| `VBACKUP_KDFITER` | Число итераций PBKDF2 для сохранения `/ENCRYPT`, не менее 1000; меньшие значения игнорируются. Только для тестов -- не уменьшайте его для настоящих saveset-ов. Число хранится в saveset-е. |
| `VBACKUP_NOHWCRYPTO` | `1` -- вычислять SHA-256 переносимым кодом даже там, где у процессора есть для этого инструкции (aarch64); для поиска неисправностей. |
| `VBACKUP_CTHREADS` | Потоки шифрования, включая вызывающий: по умолчанию по числу процессоров, не более 8; `1` -- нет. |
| `VBACKUP_ZTHREADS` | Потоки сжатия при сохранении `/DATA_FORMAT=COMPRESSED`: по умолчанию по числу процессоров, не более 8; `1` и меньше -- нет. |
| `VBACKUP_PIPELINE` | `0` -- saveset пишется без потока записи, для поиска неисправностей. Подсказки кэшу страниц остаются; saveset тот же. |
| `VBACKUP_PREFETCH` | Потоки опережающего чтения следующих файлов при сохранении или копировании: 8 по умолчанию, не более 64; `0` -- нет. Больше потоков может помочь на NFS или медленном сетевом диске, меньше -- на одном медленном жёстком диске. |
| `VBACKUP_HELPLIB` | Библиотека справки для `/HELP`. |
| `HOME` | Каталог журнала по умолчанию для пользователя, не являющегося root. |

## Глава 4 Примеры VBACKUP

1. ```
   $ vbackup /home/rrl /backup/rrl.bck /VERIFY
   %VBACKUP-I-STARTED, Operation: save, Input: /home/rrl, Output: /backup/rrl.bck - started
   %VBACKUP-I-SAVESUMM, Files: 6, Bytes: 108902, Blocks: 5, Volumes: 1 - saved
   %VBACKUP-I-VERIFYING, Saveset: /backup/rrl.bck - verifying
   %VBACKUP-I-CMPSUMM, Files: 6, Differences: 0 - compared
   %VBACKUP-I-COMPLETED, Operation: save, Seconds: 0.00 - completed
   ```

   Полное сохранение каталога `/home/rrl` в saveset `rrl.bck`. Saveset
   распознан по имени. `/VERIFY` читает новый saveset обратно и сравнивает
   каждый файл с диском; различий не найдено, код завершения 0. Хранимые
   имена начинаются с `rrl/`: база -- `/home`.

2. ```
   $ vbackup /home full.bck /RECORD /JOURNAL=/backup/home.jnl
   %VBACKUP-I-STARTED, Operation: save, Input: /home, Output: full.bck - started
   %VBACKUP-I-SAVESUMM, Files: 7, Bytes: 3108910, Blocks: 55, Volumes: 1 - saved
   %VBACKUP-I-RECORDED, Files: 5, Journal: /backup/home.jnl - recorded
   %VBACKUP-I-COMPLETED, Operation: save, Seconds: 0.01 - completed
   $ vbackup /home mon.bck /SINCE=BACKUP /RECORD /JOURNAL=/backup/home.jnl
   %VBACKUP-I-STARTED, Operation: save, Input: /home, Output: mon.bck - started
   %VBACKUP-I-SAVESUMM, Files: 3, Bytes: 4, Blocks: 4, Volumes: 1 - saved
   %VBACKUP-I-INCRSUMM, Files: 4 - unchanged, listed as present, not saved
   %VBACKUP-I-RECORDED, Files: 1, Journal: /backup/home.jnl - recorded
   %VBACKUP-I-COMPLETED, Operation: save, Seconds: 0.00 - completed
   $ vbackup full.bck,mon.bck /restore /INCREMENTAL /LOG
   %VBACKUP-I-STARTED, Operation: restore, Input: full.bck, Output: /restore - started
   %VBACKUP-I-RESTORED, File: /restore/rrl - restored
   ...
   %VBACKUP-I-RESTORED, File: /restore/rrl/new.txt - restored
   %VBACKUP-I-RESTORED, File: /restore/rrl/sub - restored
   %VBACKUP-I-DELETED, File: /restore/rrl/sub/c.h - deleted: it is not in the incremental saveset
   %VBACKUP-I-RESTSUMM, Files: 10, Bytes: 3108914 - restored
   %VBACKUP-I-COMPLETED, Operation: restore, Seconds: 0.01 - completed
   ```

   Инкрементная цепочка. Полное сохранение записывает свои файлы в журнал
   этого плана. В понедельник один файл создан и один удалён;
   `/SINCE=BACKUP` сохраняет новый файл и каталоги, а каталог saveset-а
   перечисляет четыре неизменных файла как присутствующие. Восстановление
   берёт сначала полный saveset, затем инкрементный; удалённый в
   понедельник файл удаляется из выхода. Каталоги учитываются в RESTSUMM
   при каждом своём восстановлении.

3. ```
   $ vbackup /home /mnt/usb/home.bck /VOLUME_SIZE=4G /DATA_FORMAT=COMPRESSED
   ...
   %VBACKUP-I-CREATED, Volume: /mnt/usb/home.bck.002 - created
   %VBACKUP-I-CREATED, Volume: /mnt/usb/home.bck.003 - created
   %VBACKUP-I-SAVESUMM, Files: 48211, Bytes: 10737418240, Blocks: 151216, Volumes: 3 - saved
   ...
   $ vbackup /mnt/usb/home.bck /restore
   ```

   Saveset разрезается на тома по 4 ГБ для диска FAT32, его данные
   сжимаются. О томах после первого сообщается по мере их создания. Для
   восстановления указывается первый том; остальные находятся рядом. Если
   бы том был утерян, MISSVOL назвал бы его, а файлы остальных томов всё
   равно были бы восстановлены.

4. ```
   # umask 077; head -c 32 /dev/urandom | base64 > /root/backup.key
   # vbackup /home /backup/home.bck /ENCRYPT /KEY_FILE=/root/backup.key
   # crontab -l
   30 2 * * * VBACKUP_KEY_FILE=/root/backup.key /usr/local/bin/vbackup /home /backup/home-$(date +\%a).bck /ENCRYPT /REPLACE
   ```

   Зашифрованное сохранение из cron. Файл ключа содержит пароль в первой
   строке и доступен на чтение только root; файл ключа, который могут
   читать другие, отвергается с KEYFILE. В crontab файл ключа задан через
   `VBACKUP_KEY_FILE`. У cron нет терминала: без файла ключа сохранение
   завершилось бы с NOKEY, а не ждало бы. Храните копию файла ключа в
   надёжном месте -- без неё saveset-ы не открыть.

5. ```
   $ vbackup /etc - | ssh backup-host 'cat > /backup/etc.bck'
   %VBACKUP-I-STARTED, Operation: save, Input: /etc, Output: (standard output) - started
   %VBACKUP-I-SAVESUMM, Files: 1520, Bytes: 6914304, Blocks: 120, Volumes: 1 - saved
   %VBACKUP-I-COMPLETED, Operation: save, Seconds: 0.41 - completed
   $ ssh backup-host 'cat /backup/etc.bck' | vbackup - /restore/etc
   %VBACKUP-I-STARTED, Operation: restore, Input: (standard input), Output: /restore/etc - started
   %VBACKUP-I-RESTSUMM, Files: 1520, Bytes: 6914304 - restored
   %VBACKUP-I-COMPLETED, Operation: restore, Seconds: 0.30 - completed
   ```

   Сохранение на другую машину через канал и восстановление из него.
   Сообщения идут на стандартный вывод ошибок и не смешиваются с
   saveset-ом. Saveset в канале -- один том и не проверяется; при обрыве
   канала восстановление сообщает NOTRAILER и восстанавливает то, что
   пришло.

6. ```
   # umount /dev/sdb1
   # vbackup /dev/sdb1 /mnt/usb/sdb1.bck /PHYSICAL /DATA_FORMAT=COMPRESSED
   # vbackup /mnt/usb/sdb1.bck /dev/sdc1 /PHYSICAL /REPLACE
   Everything on /dev/sdc1 (21474836480 bytes) is to be overwritten with the device saved in /mnt/usb/sdb1.bck.
   Type YES to go on: YES
   ```

   Раздел поблочно копируется на другой. Сначала он размонтируется
   (устройство, смонтированное на чтение и запись, отвергается с
   PHYSMOUNTED). Восстановление требует `/REPLACE` и, на терминале, `YES`.
   Копия несёт метки и UUID оригинала (PHYSUUID): не монтируйте оба
   одновременно.

7. ```
   # vbackup /mnt/data /mnt/usb/data.bck /IMAGE /VERIFY
   # vbackup /mnt/usb/data.bck /dev/sdc1 /IMAGE /REPLACE /LOG
   ```

   Целая файловая система сохраняется из точки монтирования вместе с
   типом, меткой и UUID. Восстановление запускает программу mkfs её типа на
   `/dev/sdc1` (при `/LOG` команду показывает IMGCMD), восстанавливает файлы в
   новую файловую систему и размонтирует её (IMGSUMM). `/dev/sdc1` может быть
   меньше исходного устройства, если файлы помещаются.

8. ```
   # vbackup /mnt/usb/home.bck /ORIGINAL
   %VBACKUP-I-STARTED, Operation: restore, Input: /mnt/usb/home.bck, Output: (where its files came from) - started
   %VBACKUP-I-ORIGTARGET, Saveset: /mnt/usb/home.bck, Target: /home - its files go back there
   %VBACKUP-W-FILEEXISTS, File: /home/rrl/a.txt - already exists, not restored
   ...
   ```

   Каждый файл возвращается в каталог, из которого был сохранён.
   Существующие файлы сохраняются, и о них сообщается; добавьте `/REPLACE`,
   чтобы перезаписать их.

9. ```
   $ vbackup /home/ivan/old /mnt/usb/old.bck /VERIFY /DELETE
   ...
   %VBACKUP-I-CMPSUMM, Files: 213, Differences: 0 - compared
   %VBACKUP-W-SRCKEPT, File: /home/ivan/old/log.txt - not deleted: it changed after it was saved
   %VBACKUP-I-DELSUMM, Deleted: 197, Kept: 1
   ```

   Файлы архивируются и затем удаляются с диска. Файл, в который писали
   после сохранения, остаётся. Каталоги остаются.

10. ```
    $ vbackup /backup/rrl.bck /COMPARE
    $ vbackup /backup/rrl.bck /tmp/restore /COMPARE
    ```

    Первая команда сравнивает saveset с местами, откуда были сохранены его
    файлы; вторая -- с каталогом, в который он был восстановлен. О каждом
    различии сообщается COMPARERR; при наличии различий код завершения 2.

11. ```
    $ vbackup /backup/rrl.bck /EXTRACT=rrl/notes.txt | less
    $ vbackup /backup/rrl.bck /tmp/notes.txt /EXTRACT=rrl/notes.txt
    ```

    Один файл извлекается на стандартный вывод, затем в файл. Имя --
    хранимое имя, как его показывает `/LIST`.

12. ```
    $ vbackup /backup/rrl.bck /LIST
    $ vbackup /backup/rrl.bck /LIST /FULL
    $ vbackup /backup/rrl.bck /LIST=/tmp/rrl.lis /FORMAT=LS
    ```

    Три формы листинга: краткая (по умолчанию), полная и по строке на файл
    в форме `ls -l`, здесь -- в файл.

13. ```
    $ vbackup /JOURNAL=/backup/home.jnl /LIST /FULL '/SELECT=*/notes.txt'
    $ rm /backup/home.jnl
    $ vbackup /backup/full.bck,/backup/mon.bck /RECORD /JOURNAL=/backup/home.jnl
    ```

    Выводится листинг журнала с известными ему файлами, имена которых
    оканчиваются на `/notes.txt`, и saveset-ом с последней копией каждого.
    Затем журнал перестраивается по каталогам saveset-ов, от старейшего.

14. ```
    # vbkx t /mnt/usb/home.bck
    /mnt/usb/home.bck: all files read, all checksums match
    # vbkx l /mnt/usb/home.bck | less
    # vbkx x /mnt/usb/home.bck -C /mnt/root/home rrl/projects
    ```

    В системе восстановления без VBACKUP статически скомпонованный vbkx
    проверяет saveset, выводит его листинг и извлекает один каталог на
    восстанавливаемый диск.

15. ```
    C:\> set VBACKUP_KEY_FILE=C:\Users\rrl\backup.key
    C:\> vbkx.exe l E:\home.bck
    C:\> vbkx.exe x E:\home.bck -C C:\restore rrl/documents
    ```

    В Windows vbkx.exe выводит листинг зашифрованного saveset-а на
    USB-диске и извлекает каталог. Имена, недопустимые в Windows, не
    извлекаются, и об этом сообщается.

## Приложение A Сообщения VBACKUP

### A.1 Формат сообщений

VBACKUP пишет сообщения на стандартный вывод ошибок, по одной строке:

```
dd-mm-yyyy hh:mm:ss.cc pid %VBACKUP-s-IDENT, text
```

| Поле | Смысл |
|---|---|
| *dd-mm-yyyy hh:mm:ss.cc* | Дата и время с точностью до сотых долей секунды |
| *pid* | Номер процесса |
| `VBACKUP` | Имя средства (facility) |
| *s* | Уровень серьёзности: S, I, W, E или F |
| `IDENT` | Идентификатор сообщения, по которому сообщения перечислены ниже |
| *text* | Текст сообщения |

Текст везде имеет одну форму: сначала то, о чём сообщение, в виде пар
`Метка: значение` -- File, Saveset, Device, Volume, Block, Files, Bytes,
errno, -- затем дефис и слова, так что имена и числа видны с первого
взгляда:

```
%VBACKUP-I-BLKFIXED, Block: 3, Volume: 1 - was bad, rebuilt from its group
```

За значением *errno* в скобках следует его текст из библиотеки C.

### A.2 Уровни серьёзности и код завершения

| Уровень | Смысл | Влияние на код завершения |
|---|---|---|
| S -- успех | Операция выполнена успешно. | Нет (0). |
| I -- информация | Сведения; всё в порядке. | Нет. |
| W -- предупреждение | Что-то было не так, как должно, но операция выполнена; результат может требовать внимания. | Не менее 1. |
| E -- ошибка | Что-то не сделано: файл, блок, сравнение или сама команда. | 2. |
| F -- фатальная ошибка | Операция не может продолжаться. | 2. |

Код завершения VBACKUP равен 2, если было выдано хотя бы одно сообщение E
или F, иначе 1, если было выдано хотя бы одно сообщение W, иначе 0.

Ошибки, обнаруженные подпрограммами командного языка StarLet ещё до того,
как VBACKUP рассматривает команду, выводятся с префиксом `%CLI_RTNS`, а не
`%VBACKUP`, -- например неоднозначное сокращение или недопустимое ключевое
слово; код завершения в этом случае 2:

```
%CLI_RTNS-F: Ambiguous qualifier 'RE'
%CLI_RTNS-E: Illegal or unrecognized keyword 'ZIP'
```

Слово, начинающееся с косой черты, но не называющее квалификатор, -- имя
файла, а не ошибка само по себе; обычно оно приводит к MAXPARM или IVOP.

vbkx и распаковщики последней надежды этим средством сообщений не
пользуются; их диагностика описана в приложении C.

### A.3 Сообщения

**ATTRERR**, File: *file* - *what* not restored, errno: *n* (*reason*)

**Средство:** VBACKUP. **Уровень:** предупреждение (W).

**Пояснение:** Атрибут восстановленного или скопированного файла не удалось
установить. *what* -- `owner`, `protection`, `times`, `flags` (флаги chattr),
`attributes` (каталога, устанавливаемые в конце восстановления), имя
расширенного атрибута или `the removal` -- файл, который `/INCREMENTAL` должен
был удалить, удалить не удалось. Данные файла восстановлены.

**Действие пользователя:** Чаще всего восстановление выполняется не от
root. Восстановите от root или задайте `/OWNER=DEFAULT`; задайте `/NOXATTRS`,
если расширенные атрибуты не нужны. Некоторые атрибуты целевая файловая
система не может хранить (например, ACL на vfat).

---

**BADREC**, Block: *block*, Volume: *volume* - an invalid record, skipped

**Средство:** VBACKUP. **Уровень:** предупреждение (W).

**Пояснение:** В потоке записей, в указанном блоке или после него,
обнаружена запись с бессмысленным заголовком или телом; она пропущена.
Окружающие блоки имели верные контрольные суммы: запись была записана
неправильно, либо saveset создан не VBACKUP. Если данные потеряны, файл, к
которому относится запись, сообщается как повреждённый.

**Действие пользователя:** Проверьте файлы, названные в FILDAMAGED. Если
saveset создан VBACKUP, сообщите о проблеме, приложив копию saveset-а.

---

**BLKFIXED**, Block: *block*, Volume: *volume* - was bad, rebuilt from its group

**Средство:** VBACKUP. **Уровень:** информация (I).

**Пояснение:** Блок saveset-а имел неверную контрольную сумму (или, в
зашифрованном saveset-е, неверный тег) и был единственным плохим блоком
своей группы; он восстановлен по остальным блокам группы и её блоку XOR.
Ничего не потеряно.

**Действие пользователя:** Для файлов -- никаких. Носитель может выходить из
строя: скопируйте saveset на другой носитель.

---

**BLKFORGED**, Block: *block*, Volume: *volume* - is not what was written: its CRC is right, its authentication fails

**Средство:** VBACKUP. **Уровень:** предупреждение (W).

**Пояснение:** Блок зашифрованного saveset-а имеет верную контрольную
сумму, но его тег аутентификации не совпадает: блок изменён умышленно (с
исправлением CRC) либо носитель ведёт себя очень странно. Блок считается
плохим: если его удалось восстановить по группе, далее следует BLKFIXED,
иначе BLKLOST.

**Действие пользователя:** Если следует BLKFIXED, файлы верны. Выясните, кто
мог писать в saveset.

---

**BLKLOST**, Block: *block*, Volume: *volume* - is bad and cannot be rebuilt

**Средство:** VBACKUP. **Уровень:** ошибка (E).

**Пояснение:** Блок saveset-а испорчен, а в его группе есть ещё один плохой
блок (или в saveset-е нет блоков XOR), поэтому восстановить его нельзя.
Чтение продолжается со следующего исправного блока. Файлы, данные которых
лежали в потерянных блоках, сообщаются FILDAMAGED или FILLOST; все остальные
файлы верны.

**Действие пользователя:** Оставьте восстановленные файлы; повреждённые
восстановите из другого saveset-а. В следующий раз задайте меньший
`/GROUP_SIZE` и храните две копии важных saveset-ов.

---

**CMPSUMM**, Files: *n*, Differences: *n* - compared

**Средство:** VBACKUP. **Уровень:** информация (I).

**Пояснение:** Итоги сравнения (`/COMPARE`, `/VERIFY`): число сравнённых
файлов и число файлов с различиями. Выводится без `/LOG`. После копирования
с `/VERIFY` выводится, только если найдены различия.

**Действие пользователя:** Никаких. При различиях см. COMPARERR.

---

**COMPARED**, File: *file* - compared

**Средство:** VBACKUP. **Уровень:** информация (I).

**Пояснение:** С `/LOG`: файл сравнён с диском, различий не найдено.

**Действие пользователя:** Никаких.

---

**COMPARERR**, File: *file* - *difference*

**Средство:** VBACKUP. **Уровень:** ошибка (E).

**Пояснение:** `/COMPARE` или `/VERIFY` сохранения или копирования нашли
различие между saveset-ом (или копией) и диском. *difference* -- одно из:
`not found on the disk`, `not a regular file on the disk`, `not a directory
on the disk`, `not a symbolic link on the disk`, `the link points elsewhere`,
`not a FIFO on the disk`, `not a device on the disk`, `the size differs`, `the
file on the disk is shorter`, `the contents differ at octet n`, а для
копирования -- `cannot be read back` или `the copy differs from the original`.
Сообщается только первое различие файла.

**Действие пользователя:** Если файл после сохранения изменён намеренно --
никаких. Иначе сохраните его снова или выясните, что его изменило. При
`/VERIFY` различие не даёт `/DELETE` ничего удалить, а `/RECORD` -- записать
сохранение.

---

**COMPLETED**, Operation: *operation*, Seconds: *s.cc* - *outcome*

**Средство:** VBACKUP. **Уровень:** информация (I).

**Пояснение:** Операция (save, restore, compare, extract, copy, rebuild of
the journal) завершилась за указанное время. *outcome* -- `completed`,
`completed with warnings` или `completed with errors`, в согласии с кодом
завершения. Выводится без `/LOG`; листинг его не выводит.

**Действие пользователя:** Никаких; если итог не `completed`, смотрите
предупреждения и ошибки выше.

---

**CONFQUAL**, Qualifiers: /*qualifier*, /*qualifier* - cannot be given together

**Средство:** VBACKUP. **Уровень:** ошибка (E).

**Пояснение:** Заданы два взаимоисключающих квалификатора. Такие пары:
`/INCREMENTAL` с `/SELECT` или `/EXCLUDE`; более одного из `/MODIFIED`,
`/CREATED`, `/CHANGED`; `/FULL` с `/BRIEF`; `/PHYSICAL` с `/SINCE`, `/BEFORE`,
`/RECORD`, `/INCREMENTAL`, `/BY_OWNER`, `/SELECT` или `/EXCLUDE`; `/IMAGE` с
`/PHYSICAL`, `/INCREMENTAL`, `/BY_OWNER`, `/SELECT` или `/EXCLUDE`; `/ORIGINAL`
с `/PHYSICAL` или `/IMAGE`; `/DELETE` с `/PHYSICAL`, `/IMAGE`, `/SINCE` или
`/BEFORE`; `/IMAGE` с `/CONFIRM` при восстановлении. Ничего не сделано.

**Действие пользователя:** Уберите один из квалификаторов.

---

**COPIED**, File: *file* - copied

**Средство:** VBACKUP. **Уровень:** информация (I).

**Пояснение:** С `/LOG`: файл скопирован операцией копирования.

**Действие пользователя:** Никаких.

---

**CPYSUMM**, Files: *n*, Bytes: *n* - copied

**Средство:** VBACKUP. **Уровень:** информация (I).

**Пояснение:** Итоги копирования: число созданных файлов и записанных байтов
данных. Выводится без `/LOG`.

**Действие пользователя:** Никаких.

---

**CRCERR**, File: *file* - checksum mismatch: the data differ from what was saved

**Средство:** VBACKUP. **Уровень:** ошибка (E).

**Пояснение:** Данные восстановленного или извлечённого файла не совпадают с
CRC, записанной при сохранении, хотя все блоки прочитаны верно. Файл
записан, но его содержимое -- не то, что сохранялось. Это же сообщение даёт
saveset со сжатыми данными, читаемый VBACKUP версии до X01-04.

**Действие пользователя:** Не доверяйте файлу; восстановите его из другого
saveset-а. Используйте текущую версию VBACKUP. Если saveset создан и прочитан
одной и той же версией VBACKUP, сообщите о проблеме.

---

**CREATED**, Volume: *volume* - created

**Средство:** VBACKUP. **Уровень:** информация (I).

**Пояснение:** Создан том saveset-а. О томе 1 сообщается только при `/LOG`; о
каждом следующем -- всегда.

**Действие пользователя:** Никаких. Если тома идут на сменные носители,
храните их вместе.

---

**DELETED**, File: *file* - deleted: it is not in the incremental saveset

**Средство:** VBACKUP. **Уровень:** информация (I).

**Пояснение:** Восстановление `/INCREMENTAL` удалило файл из каталога
saveset-а, потому что каталог saveset-а его не перечисляет: файл был удалён
до этого сохранения. Выводится при `/LOG`.

**Действие пользователя:** Никаких.

---

**DELSUMM**, Deleted: *n*, Kept: *n*

**Средство:** VBACKUP. **Уровень:** информация (I).

**Пояснение:** Итоги `/DELETE`: число файлов, удалённых после сохранения и
проверки, и число оставленных.

**Действие пользователя:** Если файлы оставлены, см. SRCKEPT.

---

**ENCRYPTED**, Saveset: *saveset*, Iterations: *n* - encrypted: ChaCha20, HMAC-SHA256, PBKDF2

**Средство:** VBACKUP. **Уровень:** информация (I).

**Пояснение:** С `/LOG`: saveset записывается зашифрованным; *n* -- число
итераций PBKDF2 для его ключей.

**Действие пользователя:** Никаких. Если *n* меньше 600000, задана
`VBACKUP_KDFITER`: уберите её для настоящих saveset-ов.

---

**FATALSAVE**, Saveset: *saveset* - could not be completed

**Средство:** VBACKUP. **Уровень:** фатальная ошибка (F).

**Пояснение:** Saveset не удалось записать до конца: не записался том
(перед этим -- WRITERR), не записался каталог или кончилась память. Saveset
оставлен как есть, без TRAILER; он не проверяется, и ничего не
записывается в журнал и не удаляется.

**Действие пользователя:** Устраните сообщённую ранее причину (чаще всего --
переполненный диск) и сохраните снова. Файлы, записанные до обрыва, можно
восстановить из неполного saveset-а.

---

**FILCHANGED**, File: *file* - changed while it was being saved

**Средство:** VBACKUP. **Уровень:** предупреждение (W).

**Пояснение:** Размер, время изменения или время смены атрибутов файла после
чтения отличались от прежних: в файл писали во время сохранения, и копия
может оказаться смесью старого и нового. Файл сохраняется в состоянии
CHANGED и не записывается в журнал, поэтому следующее `/SINCE=BACKUP`
сохранит его снова. Копирование сообщает об этом так же.

**Действие пользователя:** Сохраните файл снова, когда в него никто не
пишет, или сохраняйте со снимка (LVM, btrfs).

---

**FILDAMAGED**, File: *file* - is incomplete: its data was lost in bad blocks

**Средство:** VBACKUP. **Уровень:** ошибка (E).

**Пояснение:** Часть данных файла лежала в потерянных блоках (BLKLOST,
MISSVOL); файл восстановлен, сравнён или извлечён настолько, насколько его
данные удалось прочитать. При восстановлении `/PHYSICAL` у устройства
потеряны части. Это же сообщение даёт saveset со сжатыми данными, читаемый
VBACKUP версии до X01-04.

**Действие пользователя:** Восстановите файл из другого saveset-а. Все файлы,
не названные в сообщениях, верны.

---

**FILEEXISTS**, File: *file* - already exists, not restored

**Средство:** VBACKUP. **Уровень:** предупреждение (W).

**Пояснение:** Восстанавливаемый, копируемый или извлекаемый файл существует,
а `/REPLACE` не задан; существующий файл оставлен.

**Действие пользователя:** Задайте `/REPLACE`, чтобы перезаписать его, или
восстанавливайте в другой каталог.

---

**FILLOST**, File: *file* - not restored: its records were lost in bad blocks

**Средство:** VBACKUP. **Уровень:** ошибка (E).

**Пояснение:** Каталог перечисляет файл, который так и не появился в потоке:
его запись FILE была в потерянных блоках. Файла нет в выходе.

**Действие пользователя:** Восстановите файл из другого saveset-а.

---

**GLUED**, Parameter: *word* - the qualifiers glued to it are taken as qualifiers

**Средство:** VBACKUP. **Уровень:** информация (I).

**Пояснение:** К параметру были приклеены квалификаторы, как в
`x.sav/sav/log`; VBACKUP разделил их, как это делает DCL. Сообщение
выводится, чтобы опечатка в имени файла не была незаметно принята за
квалификатор.

**Действие пользователя:** Никаких, если так и задумано. Если слово было
именем файла, задайте его как есть (имя существующего файла никогда не
разрезается) или отделите квалификаторы пробелами.

---

**IMGCMD**, Command: *command*

**Средство:** VBACKUP. **Уровень:** информация (I).

**Пояснение:** С `/LOG`: восстановление `/IMAGE` сейчас запустит команду,
создающую новую файловую систему.

**Действие пользователя:** Никаких.

---

**IMGMKFS**, Command: *command* - failed: *reason*

**Средство:** VBACKUP. **Уровень:** ошибка (E).

**Пояснение:** Команда, создающая новую файловую систему при восстановлении
`/IMAGE`, не выполнилась. *reason* -- `the program is not installed`,
последняя выведенная программой строка, `it failed` или причина, по которой
программу не удалось запустить. Ничего не восстановлено.

**Действие пользователя:** Установите программу (e2fsprogs, xfsprogs,
btrfs-progs, dosfstools) или устраните сообщённую ею причину и восстановите
снова.

---

**IMGMOUNT**, Type: *type*, Device: *device*, errno: *n* - the new file system cannot be mounted (*reason*)

**Средство:** VBACKUP. **Уровень:** ошибка (E).

**Пояснение:** Только что созданную на устройстве при восстановлении `/IMAGE`
файловую систему не удалось смонтировать во временный каталог. Ничего не
восстановлено.

**Действие пользователя:** Убедитесь, что ядро поддерживает этот тип
файловой системы и что VBACKUP запущен от root.

---

**IMGNOID**, Volume: *mount-point* - the *UUID* of its file system is not known: the new one gets a new one

**Средство:** VBACKUP. **Уровень:** предупреждение (W).

**Пояснение:** Сохранение `/IMAGE` не нашло UUID файловой системы (ни в
`/dev/disk/by-uuid`, ни, для файловых систем ext, в суперблоке). Saveset
создаётся; восстановление `/IMAGE` создаст файловую систему с новым UUID.

**Действие пользователя:** Если UUID важен (например, на него ссылается
`/etc/fstab`), установите его на новой файловой системе после
восстановления.

---

**IMGNOTIMG**, Saveset: *saveset* - was not made with /IMAGE: restore it without /IMAGE

**Средство:** VBACKUP. **Уровень:** ошибка (E).

**Пояснение:** Восстановлению `/IMAGE` задан saveset без идентичности
файловой системы.

**Действие пользователя:** Восстановите saveset без `/IMAGE`, в каталог.

---

**IMGNOTMNT**, Device: *device* - is not mounted: mount it (read-only is enough) and give the mount point or the device

**Средство:** VBACKUP. **Уровень:** ошибка (E).

**Пояснение:** Вход сохранения `/IMAGE` -- несмонтированное блочное
устройство; VBACKUP читает файлы через смонтированную файловую систему.

**Действие пользователя:** Смонтируйте устройство, можно только на чтение, и
сохраните снова.

---

**IMGNOTVOL**, File: *file* - is neither the mount point of a file system nor a device: /IMAGE saves a whole volume

**Средство:** VBACKUP. **Уровень:** ошибка (E).

**Пояснение:** Вход сохранения `/IMAGE` -- не точка монтирования файловой
системы (например, подкаталог) и не смонтированное блочное устройство.

**Действие пользователя:** Задайте точку монтирования или сохраните каталог
без `/IMAGE`.

---

**IMGSMALL**, Device: *device*, Bytes: *n*, Needed: *n* - too small, nothing written

**Средство:** VBACKUP. **Уровень:** ошибка (E).

**Пояснение:** Выходное устройство восстановления `/IMAGE` меньше места,
занятого сохранённой файловой системой, плюс 5%, плюс 16 МБ на метаданные
новой файловой системы.

**Действие пользователя:** Используйте устройство большего размера.

---

**IMGSUMM**, Device: *device*, Type: *type*, Files: *n*, Bytes: *n* - file system made, files restored

**Средство:** VBACKUP. **Уровень:** информация (I).

**Пояснение:** Итоги восстановления `/IMAGE`: файловая система создана на
устройстве, файлы восстановлены в неё.

**Действие пользователя:** Никаких.

---

**IMGUNSUPP**, Saveset: *saveset*, Type: *type* - VBACKUP does not make such a file system: use /PHYSICAL for it

**Средство:** VBACKUP. **Уровень:** ошибка (E).

**Пояснение:** Saveset содержит файловую систему типа, для которого VBACKUP
не умеет создавать новую файловую систему (создаются типы ext2, ext3, ext4,
xfs, btrfs, vfat, msdos).

**Действие пользователя:** Восстановите файлы в каталог без `/IMAGE` или
сохраняйте такие тома с `/PHYSICAL`.

---

**INCRSUMM**, Files: *n* - unchanged, listed as present, not saved

**Средство:** VBACKUP. **Уровень:** информация (I).

**Пояснение:** Инкрементное сохранение (задан фильтр времени) перечислило в
каталоге *n* охваченных файлов как присутствующие, не сохраняя их.

**Действие пользователя:** Никаких.

---

**IVOP**, cannot tell what to do: *reason*

**Средство:** VBACKUP. **Уровень:** ошибка (E).

**Пояснение:** Операцию нельзя определить по параметрам: вход не существует
(а значит, не является saveset-ом), а выход не является именем saveset-а.

**Действие пользователя:** Проверьте входную спецификацию. Для сохранения

**IVQUAL**, Value: *value*, Qualifier: /*qualifier* - is not valid

**Средство:** VBACKUP. **Уровень:** ошибка (E).

**Пояснение:** Недопустимое значение квалификатора: `/BLOCK_SIZE` вне
пределов 8192..1048576 или не кратно 512; `/GROUP_SIZE` больше 100;
`/VOLUME_SIZE` -- не размер или меньше (размер группы + 3) x размер блока;

**Действие пользователя:** Исправьте значение.

---

**IVTIME**, Time: *value*, Qualifier: /*qualifier* - is not a valid time

**Средство:** VBACKUP. **Уровень:** ошибка (E).

**Пояснение:** Значение `/SINCE` или `/BEFORE` -- не время, понятное VBACKUP.

**Действие пользователя:** Запишите время, как описано в разделе `/BEFORE`
главы 3.

---

**JNLERR**, Journal: *journal* - *what*, errno: *n* (*reason*)

**Средство:** VBACKUP. **Уровень:** ошибка (E).

**Пояснение:** Журналом нельзя воспользоваться. *what* -- одно из: `no
journal given, and no home directory`; `cannot make its directory`; `cannot
be opened` (журнал или его файл блокировки); `cannot be locked`; `cannot be
read, or is too short`; `is no journal, or is damaged`; `cannot be created`,
`cannot be written` (временный файл); `cannot be replaced`. Сохранение с
`/SINCE=BACKUP` или `/RECORD`, не сумевшее открыть журнал, не выполняется.

**Действие пользователя:** Устраните причину, указанную в *reason*.
Испорченный журнал можно перестроить: удалите его и задайте saveset-ы с
`/RECORD`.

---

**KEYFILE**, Key file: *file* - *reason*

**Средство:** VBACKUP. **Уровень:** ошибка (E).

**Пояснение:** Пароль нельзя взять из файла ключа или с терминала (тогда
*file* -- `/dev/tty`). *reason* -- причина, по которой файл не удалось
открыть или прочитать; `not a regular file`; `others may read or change it -
chmod 600 it`; `its first line is longer than 1024 bytes`; `its first line is
empty`; для терминала -- `an empty passphrase` или `longer than 1024 bytes, or
no line`. Ничего не прочитано и не записано.

**Действие пользователя:** Сделайте файл ключа обычным файлом, доступным
только владельцу (`chmod 600 file`), с паролем в первой строке.

**Пояснение:** Сохранение `/ENCRYPT` дважды запросило пароль на терминале, и
ответы не совпали. Saveset не создан.

**Действие пользователя:** Сохраните снова и дважды введите один и тот же

**Действие пользователя:** Исправьте команду; разделяйте несколько входов
запятыми без пробелов.

---

**MISSING**, File: *file* - should be there from an earlier saveset, and is not

**Средство:** VBACKUP. **Уровень:** предупреждение (W).

**Пояснение:** При восстановлении `/INCREMENTAL` каталог перечисляет файл как
присутствующий (не изменившийся с прежнего сохранения), но ни один

**MISSVOL**, Volume: *n*, Saveset: *saveset* - is missing

---

**NOTFOUND**, File: *name* - is not in the saveset

---

**NOTINCR**, Saveset: *saveset* - *reason*: nothing restored with /INCREMENTAL

**Средство:** VBACKUP. **Уровень:** ошибка (E).

**Пояснение:** Восстановление `/INCREMENTAL` отвергло saveset, потому что не
может доверять его списку файлов: `it does not say whether it is full or
incremental (written before X01-02)`, `it has no catalog`, `its catalog

восстанавливается, и на нём цепочка обрывается.

**Действие пользователя:** Восстановите этот saveset без `/INCREMENTAL`.

**NOTOPIC**, Topic: *topic* - sorry, no documentation on it

**NOTRAILER**, Saveset: *saveset* - has no trailer: the save did not complete, or its last volume is missing

**Пояснение:** Последний блок saveset-а -- не TRAILER: сохранение было

восстановить; saveset читается последовательно. Перестройка журнала такой
saveset пропускает.

**Действие пользователя:** Найдите недостающий том, если он есть. Иначе
восстановите то, что можно, и создайте новый saveset.

**Действие пользователя:** Задайте первый том одного saveset-а.

**OPENDIR**, Directory: *directory*, errno: *n* - cannot be read (*reason*)

**Пояснение:** Каталог, встреченный при сохранении или копировании, не
удалось открыть или прочитать; его содержимое не сохраняется.

**Действие пользователя:** Выполните сохранение от пользователя, который

---

**OPENIN**, File: *file*, errno: *n* - cannot be opened as input (*reason*)

**Средство:** VBACKUP. **Уровень:** ошибка (E).

**Пояснение:** Файл не удалось открыть на чтение: файл или база спецификации
при сохранении или копировании, saveset, устройство сохранения `/PHYSICAL`,
вход сохранения `/IMAGE`, сравниваемый файл; либо имя слишком длинное
(errno 36). Если вход команды не существует и выход не задан, OPENIN
сообщает об этом с errno 2.

**Действие пользователя:** Проверьте имя и права доступа.

---

**OPENOUT**, File: *file*, errno: *n* - cannot be created as output (*reason*)

**Средство:** VBACKUP. **Уровень:** ошибка (E).

**Пояснение:** Файл не удалось создать: том saveset-а (errno 17, File
exists, если он существует и `/REPLACE` не задан), восстанавливаемый,
копируемый или извлекаемый файл, файл листинга `/LIST=file`, временный
спул каталога, выход восстановления `/PHYSICAL` или `/IMAGE`. С errno 22 и
причиной `a name that leads out of the output directory` saveset содержит
имя с `..` или ведущей `/`; такой файл никогда не записывается. Имя, путь к
которому проходит через символическую ссылку, отвергается так же.

**Действие пользователя:** Проверьте права доступа и свободное место;
задайте `/REPLACE`, чтобы перезаписать saveset. Имя, ведущее за пределы
выходного каталога, означает, что saveset создан не VBACKUP или создан во
вред.

**RECORDED**, Files: *n*, Journal: *journal* - recorded

**Средство:** VBACKUP. **Уровень:** информация (I).

**Пояснение:** Журнал обновлён сохранением `/RECORD` (записано *n* файлов)
или перестроен по каталогам.

**Действие пользователя:** Никаких.

---

**RESTORED**, File: *file* - restored

**Средство:** VBACKUP. **Уровень:** информация (I).

**Пояснение:** С `/LOG`: файл восстановлен.

**Действие пользователя:** Никаких.

---

**RESTSUMM**, Files: *n*, Bytes: *n* - restored

**Средство:** VBACKUP. **Уровень:** информация (I).

**Пояснение:** Итоги восстановления: число созданных файлов и каталогов и
записанных байтов данных по всем saveset-ам команды. Выводится без `/LOG`.

**Действие пользователя:** Никаких.

---

**SAVED**, File: *stored-name* - saved

**Средство:** VBACKUP. **Уровень:** информация (I).

**Пояснение:** С `/LOG`: файл сохранён.

**Действие пользователя:** Никаких.

---

**SAVESUMM**, Files: *n*, Bytes: *n*, Blocks: *n*, Volumes: *n* - saved

**Средство:** VBACKUP. **Уровень:** информация (I).

**Пояснение:** Итоги сохранения: сохранённые файлы, сохранённые байты данных,
записанные блоки всех типов, тома. Выводится без `/LOG`.

**Действие пользователя:** Никаких.

---

**SKIPPED**, File: *stored-name* - skipped: *reason*

**Средство:** VBACKUP. **Уровень:** информация (I).

**Пояснение:** С `/LOG`: файл или каталог не включён в сохранение или
копирование; *reason* -- `nodump flag set`.

**Действие пользователя:** Никаких. Чтобы сохранить такие файлы, задайте
`/IGNORE=NOBACKUP`.

---

**SRCDELETED**, File: *file* - deleted: it is in the saveset and verified

**Средство:** VBACKUP. **Уровень:** информация (I).

**Пояснение:** С `/DELETE /LOG`: файл удалён после сохранения и проверки.

**Действие пользователя:** Никаких.

---

**SRCKEPT**, File: *file* - not deleted: *reason*

**Средство:** VBACKUP. **Уровень:** предупреждение (W).

**Пояснение:** `/DELETE` оставил файл. *reason* -- `it changed after it was
saved`, причина неудачи удаления либо -- при *file*, равном `every file`, --
`the saveset did not verify` или `a saveset on the standard output cannot be
verified`.

**Действие пользователя:** Сохраните файл снова, если он изменился; при
необходимости удалите его вручную.

---

**STARTED**, Operation: *operation*, Input: *input*[, Output: *output*] - started

**Средство:** VBACKUP. **Уровень:** информация (I).

**Пояснение:** Операция начинается. *operation* -- `save`, `restore`,
`compare`, `extract`, `copy` или `rebuild of the journal`. Стандартный ввод и
вывод показываются как `(standard input)` и `(standard output)`; выход
восстановления `/ORIGINAL` -- как `(where its files came from)`. При
нескольких входных спецификациях показывается первая. Выводится без
`/LOG`; листинг его не выводит.

**Действие пользователя:** Никаких.

---

**TOODEEP**, Directory: *directory*, Levels: *n* - nested deeper, not descended

**Средство:** VBACKUP. **Уровень:** предупреждение (W).

**Пояснение:** Каталог, встреченный при сохранении или копировании, вложен
глубже 256 уровней ниже базы; его содержимое не сохраняется.

**Действие пользователя:** Сохраните этот каталог отдельной спецификацией.

---

**TOOMANY**, Too many: *what*, Taken: *n* - the rest is ignored

**Средство:** VBACKUP. **Уровень:** предупреждение (W).

**Пояснение:** Задано более 64 входных спецификаций или более 64 шаблонов
`/SELECT` или `/EXCLUDE`; берутся первые 64.

**Действие пользователя:** Используйте меньше спецификаций или шаблонов:
шаблон, общий каталог, более широкий шаблон.

---

**UNNAMED**, Saveset: *saveset* - blocks were lost and *reason*: files missing from the restore cannot all be named

**Средство:** VBACKUP. **Уровень:** предупреждение (W).

**Пояснение:** При восстановлении потеряны блоки, а у saveset-а нет каталога,
его каталог не читается или испорчен, поэтому файлы, записи которых
потеряны, нельзя все назвать сообщениями FILLOST. Некоторых файлов в выходе
может не быть.

**Действие пользователя:** Сравните выход с источником или с листингом
более старого saveset-а.

---

**UNSUPP**, File: *file* - *what* not restored, errno: *n* (*reason*)

**Средство:** VBACKUP. **Уровень:** предупреждение (W).

**Пояснение:** Файл типа, который здесь нельзя создать, не восстановлен: `an
unknown file type`; `a special file`, который не удалось создать (файл
устройства, восстанавливаемый не от root, сокет); или для `/EXTRACT` --
`anything but a regular file`.

**Действие пользователя:** Восстанавливайте файлы устройств от root.
Извлекать можно только обычные файлы.

---

**VERIFYING**, Saveset: *saveset* - verifying

**Средство:** VBACKUP. **Уровень:** информация (I).

**Пояснение:** `/VERIFY`: только что записанный saveset читается обратно и
сравнивается с диском.

**Действие пользователя:** Никаких.

---

**WRITERR**, File: *file*, errno: *n* - cannot be written (*reason*)

**Средство:** VBACKUP. **Уровень:** ошибка (E).

**Пояснение:** Ошибка записи: тома saveset-а (сохранение затем завершается
FATALSAVE), спула каталога, восстанавливаемого или извлекаемого файла,
стандартного вывода, файла листинга или выходного устройства
восстановления `/PHYSICAL`.

**Действие пользователя:** Чаще всего выход переполнен (errno 28): освободите
место или разрежьте saveset на тома и повторите операцию.

---

**WRONGKEY**, Saveset: *saveset* - the passphrase does not open it

**Средство:** VBACKUP. **Уровень:** ошибка (E).

**Пояснение:** Заданный пароль не соответствует контрольному значению ключа
зашифрованного saveset-а. Ничего не прочитано и не записано. Пароль не
сохраняется: для следующего saveset-а команды он будет запрошен снова.

**Действие пользователя:** Проверьте файл ключа: учитывается только первая
строка, регистр букв важен. Saveset, пароль которого утерян, не откроет
никто.

---

**WRONGVOL**, Volume: *n*, Saveset: *saveset* - belongs to another saveset, ignored

**Средство:** VBACKUP. **Уровень:** предупреждение (W).

**Пояснение:** Файл с именем тома saveset-а принадлежит другому saveset-у
(отличается идентификатор saveset-а) или вообще не является томом. Он
пропускается; обычно далее следует MISSVOL для этого тома.

**Действие пользователя:** Поместите на его место нужный том. Не смешивайте
тома saveset-ов, сохранённых под одним именем.

## Приложение B Сводка формата saveset-а

Это приложение кратко излагает формат saveset-а версии 1. Определяющее
описание -- `doc/format.md`; читающая программа, написанная только по этому
документу, должна уметь выводить листинг и восстанавливать любой saveset.
Начиная с X01-08 saveset можно читать и со стандартного ввода (см. раздел
1.9); фраза `format.md`, раздел 8, исключающая это, относится только к
этапу 1.

### B.1 Соглашения

- Все целые -- little-endian, беззнаковые, если не оговорено иное (u8, u16,
  u32, u64; i64 -- в дополнительном коде). Поля кодируются побайтно.
- TIME -- 12 байт: i64 секунд с 1970-01-01 00:00:00 UTC, u32 наносекунд.
- Строки и пути -- сырые байты без завершающего NUL; кодировка не
  предполагается.
- CRC -- CRC-32/IEEE (отражённый полином 0xEDB88320, начальное значение и
  итоговое XOR 0xFFFFFFFF; CRC("123456789") = 0xCBF43926), не CRC-32C.
- UUID -- 16 случайных байт, версия 4.

### B.2 Тома и блоки

```
volume 1 : VHDR  G G G ... G
volume 2 : VHDR  G G ... G
...
volume K : VHDR  G G ... G  TRAILER

G (group) = DATA x n, then XOR        (1 <= n <= N; N = 0: no XOR blocks)
```

Том *k* >= 2 называется *имя*`.`*k*, не менее трёх цифр. Группа никогда не
пересекает границу тома. Размер блока B -- от 8192 до 1048576, кратен 512;
полезная нагрузка блока -- P = B - 64 байта. Блоки нумеруются с 0 через
весь saveset.

### B.3 Заголовок блока (64 байта)

| Смещение | Размер | Поле | Смысл |
|---|---|---|---|
| 0 | 4 | magic | `V` `B` `K` `B` |
| 4 | 2 | hdrlen | 64 |
| 6 | 2 | version | 1 |
| 8 | 4 | bsize | B |
| 12 | 1 | type | 1 DATA, 2 XOR, 3 VHDR, 4 TRAILER, 5 EDATA, 6 ETRAILER |
| 13 | 1 | flags | бит 0 LASTINVOL, бит 1 LASTINSET |
| 14 | 2 | gindex | DATA: позиция в группе; XOR: n; иначе 0 |
| 16 | 16 | ssuuid | UUID saveset-а |
| 32 | 8 | blkno | номер блока |
| 40 | 4 | volno | номер тома, с 1 |
| 44 | 4 | recoff | DATA: смещение первого заголовка записи, начинающейся в блоке; 0xFFFFFFFF, если такой нет |
| 48 | 4 | paylen | DATA: занятые байты нагрузки; VHDR, TRAILER: длина тела TLV; XOR: P |
| 52 | 4 | prvrecoff | recoff предыдущего блока DATA группы, 0xFFFFFFFF для первого |
| 56 | 4 | prvpaylen | paylen предыдущего блока DATA группы, 0 для первого |
| 60 | 4 | crc | CRC заголовка (с этим полем, равным 0) и всей области нагрузки |

Нагрузка блока XOR -- XOR областей нагрузки по P байт n блоков DATA его
группы. Один плохой блок DATA восстанавливается по ней; его `recoff` и
`paylen` берутся из `prvrecoff` и `prvpaylen` следующего за ним блока.

### B.4 Типы блоков

| Тип | Имя | Содержимое |
|---|---|---|
| 1 | DATA | Часть потока записей |
| 2 | XOR | Чётность блоков DATA своей группы (никогда не шифруется) |
| 3 | VHDR | Первый блок каждого тома: полная запись SUMMARY (в зашифрованном saveset-е -- краткая открытая SUMMARY) |
| 4 | TRAILER | Последний блок saveset-а: одно тело TLV с итогами и местом каталога |
| 5 | EDATA | Блок DATA зашифрованного saveset-а |
| 6 | ETRAILER | TRAILER зашифрованного saveset-а |

### B.5 Записи

Заголовок записи, 8 байт: u16 тип, u16 флаги (0), u32 длина тела. Запись
может пересекать границы блоков и томов; её заголовок -- никогда.

| Тип | Запись | Тело |
|---|---|---|
| 1 | SUMMARY | элементы TLV |
| 2 | FILE | элементы TLV (теги файла) |
| 3 | DATA | u32 fileno, u32 0, u64 смещение, данные (не более 1048576 байт) |
| 4 | FEND | элементы TLV: FILENO, SIZE, CRC, STATUS |
| 5 | CATALOG | элементы: u32 длина элемента, элементы TLV |
| 6 | END | элементы TLV: NFILES, NBYTES, NERRORS |
| 7 | DATAZ | u32 fileno, u32 кодек (1 = блок LZ4), u64 смещение, u32 rawlen, сжатые байты |

Порядок в потоке:

```
SUMMARY
  ( FILE [DATA|DATAZ ...] FEND ) ...   one group per file
  CATALOG ...                          at most 1 MiB body each
END
```

Запись неизвестного типа и элемент TLV с неизвестным тегом читающий
пропускает по их длине.

### B.6 Теги

Элемент TLV -- u16 тег, u32 длина, значение. Для всех записей одно
пространство тегов.

| Теги | Группа | Имена |
|---|---|---|
| 1-20 | Теги файла (FILE, CATALOG) | FILENO, PATH, FTYPE (1 REG, 2 DIR, 3 SYMLINK, 4 HARDLINK, 5 CHR, 6 BLK, 7 FIFO, 8 SOCK), MODE, UID, GID, UNAME, GNAME, SIZE, MTIME, ATIME, CTIME, BTIME, RDEV, LINK, XATTR, FSFLAGS, DEVINO, BASEIDX, NLINK |
| 32-36 | FEND, CATALOG | CRC, STATUS (0 OK, 1 CHANGED, 2 READERR, 3 PRESENT -- только в каталоге), LOCVOL, LOCBLK, LOCOFF |
| 64-77 | SUMMARY | PRODUCT, HOST, USER, CMDLINE, CREATED, BASE, BLOCKSIZE, GROUPSIZE, VOLSIZE, COMMENT, SYSTEM, KIND (0 FULL, 1 INCREMENTAL), FILTER, COMPRESS |
| 78-80 | SUMMARY, /PHYSICAL | PHYSICAL, DEVSIZE, SECTORSIZE |
| 81-87 | SUMMARY, /IMAGE | IMAGE, FSTYPE, FSLABEL, FSUUID, FSUSED, ROOTATTR, MOUNTOPTS |
| 88-92 | VHDR и SUMMARY, шифрование | CIPHER (1), KDF (1), KDFITER, SALT, KEYCHECK |
| 96-104 | END, TRAILER | NFILES, NBYTES, NERRORS, NBLOCKS, CATVOL, CATBLK, CATOFF, NVOLS, NENTRIES |
| 128-130 | Журнал | SSUUID, SPEC, RECORDED |

### B.7 Шифрование (format.md, 6.10)

- Примитивы: ChaCha20 (RFC 8439) и SHA-256 (FIPS 180-4), с построенными на
  нём HMAC-SHA256 и PBKDF2-HMAC-SHA256.
- Ключи:

  ```
  MK    = PBKDF2-HMAC-SHA256(passphrase, SALT, KDFITER, 32 bytes)
  KENC  = HMAC-SHA256(MK, "VBACKUP ENC")
  KMAC  = HMAC-SHA256(MK, "VBACKUP MAC")
  CHECK = HMAC-SHA256(MK, "VBACKUP CHECK")     stored as KEYCHECK
  ```

- Область нагрузки EDATA и ETRAILER: шифротекст (`paylen` байт), нули и
  32-байтный TAG по смещению P - 32; `paylen` не больше P - 32.
- Шифрование: шифротекст = открытый текст XOR ChaCha20(KENC, nonce = u32 0
  || u64 blkno, счётчик с 0).
- TAG = HMAC-SHA256(KMAC, ssuuid || bsize || blkno || volno || type || gindex
  || recoff || paylen || шифротекст). Блок с верным CRC и неверным TAG --
  плохой блок. TAG проверяется до расшифровки.
- VHDR несёт в открытом виде только PRODUCT, BLOCKSIZE, GROUPSIZE, VOLSIZE,
  CIPHER, KDF, KDFITER, SALT и KEYCHECK; полная SUMMARY -- первая запись
  зашифрованного потока.
- CRC и блоки XOR вычисляются по шифротексту: проверке и починке пароль не
  нужен.

### B.8 Журнал

Отдельный файл: 16-байтный заголовок (`V` `B` `K` `J`, u16 версия 1, u16
резерв, u64 число записей), записи в формате записей saveset-а -- SSET (тип
16) для saveset-а, FSTATE (тип 17) для файла -- и завершающий u32 CRC всего
предыдущего. Ключ FSTATE -- абсолютное имя файла. Журнал переписывается
целиком через `журнал.tmp` под исключительной блокировкой `журнал.lock`.

## Приложение C Автономный распаковщик vbkx

### C.1 Описание

vbkx читает saveset-ы, созданные VBACKUP, на машине, где VBACKUP не
установлен: в системе восстановления, в другом дистрибутиве, в файловом
менеджере. Он собран только из ядра чтения VBACKUP -- без командного языка,
библиотеки справки и средства сообщений -- и скомпонован статически там,
где система это позволяет: скопируйте один файл и запустите.

### C.2 Формат

```
vbkx l saveset [-m] [-k keyfile] [-n]
vbkx x saveset [-C dir] [-f] [-j] [-k keyfile] [-n] [name ...]
vbkx p saveset name [-k keyfile] [-n]
vbkx t saveset [-k keyfile] [-n]
```

Сначала идёт буква команды, затем saveset (первый том или `-` для
стандартного ввода), затем ключи и имена в любом порядке.

### C.3 Команды

| Команда | Действие |
|---|---|
| `l` | Выводит файлы, по строке на файл, из каталога (или из потока, если каталога нет). |
| `x` | Извлекает все файлы за один проход или только заданные имена, каждое через каталог. Имя каталога берёт всё, что под ним. |
| `p` | Пишет один файл на стандартный вывод. |
| `t` | Читает весь saveset и проверяет все контрольные суммы; при успехе выводит *saveset*`: all files read, all checksums match`. |

Листинг имеет вид (время местное):

```
2026-10-05 14:19:25         4096 d0755 rrl
2026-10-05 14:19:25            6 -0644 rrl/a.txt
2026-10-05 14:19:25            5 l0777 rrl/link -> a.txt
```

Буквы типов -- как у `ls`: `-` `d` `l` `h` (жёсткая ссылка, за которой следует
`link to` *имя*) `c` `b` `p` `s`, затем режим в восьмеричном виде.

### C.4 Ключи

| Ключ | Команды | Смысл |
|---|---|---|
| `-C dir` | x | Извлекать в *dir*, создаваемый при отсутствии; по умолчанию -- текущий каталог. |
| `-f` | x | Перезаписывать существующие файлы; без него они оставляются, и об этом сообщается. |
| `-j` | x | Извлекать файлы по последнему компоненту имени, без каталогов («извлечь без пути» MultiArc). |
| `-m` | l | Листинг без `-> цель`, для программ. |
| `-k keyfile` | все | Пароль зашифрованного saveset-а: первая строка *keyfile*, который может читать только владелец (режим 600). |
| `-n` | все | Никогда не спрашивать пароль (для программ); то же делает `VBACKUP_NOPROMPT=1`. |

Без `-k` используется файл ключа, названный `VBACKUP_KEY_FILE`; без того и
другого пароль запрашивается на терминале (в Windows -- на консоли).

### C.5 Что восстанавливается

vbkx восстанавливает данные и дыры, режим, времена изменения и доступа,
каталоги, символические и жёсткие ссылки и FIFO; под root -- также
владельца (по номеру) и файлы устройств. ACL, расширенные атрибуты и флаги
chattr он не восстанавливает; когда они нужны, восстанавливайте VBACKUP.

Именам saveset-а не доверяют: имя с `..`, ведущей `/` или путём через
символическую ссылку отвергается, каждый каталог на пути открывается с
O_NOFOLLOW. Повреждения чинятся, насколько позволяют блоки XOR; каждый
обрезанный файл называется `is incomplete`, каждый файл каталога, до
которого не удалось добраться, -- `not extracted`. Из канала (`-`) saveset
выводится и извлекается по мере чтения; имена отвергаются, потому что его
каталог идёт последним.

### C.6 Диагностика

vbkx пишет диагностику на стандартный вывод ошибок с префиксом `vbkx:` в
форме сообщений VBACKUP -- `Метка: значение - слова`, -- но без даты, номера
процесса и идентификатора сообщения:

```
vbkx: Block: 3, Volume: 1 - is bad and cannot be rebuilt
vbkx: File: rrl/big.bin - checksum mismatch: the data differ from what was saved
vbkx: File: rrl/big.bin - is incomplete: its data was lost in bad blocks
vbkx: Saveset: e.bck - the passphrase does not open it
```

### C.7 Коды завершения

| Код | Смысл |
|---|---|
| 0 | Сделано. |
| 1 | Что-то повреждено или не сделано (файл неполон, не извлечён, существует, атрибут не установлен). |
| 2 | Команду или saveset нельзя использовать (неверная команда, не saveset, не открывается, неверный или отсутствующий пароль, выходной каталог не создаётся). |

### C.8 vbkx.exe в Windows

vbkx.exe принимает те же команды. Имена, в saveset-е в UTF-8, становятся
UTF-16 под `\\?\`, поэтому длинные пути работают. Восстанавливаются данные,
размеры, времена, атрибут «только чтение» (нет бита записи у владельца),
каталоги и жёсткие ссылки; символические ссылки -- там, где Windows это
позволяет (режим разработчика или право их создавать), иначе об этом
сообщается. FIFO, файлы устройств, владельцы и режимы сверх «только чтение»
не создаются. Имя, недопустимое в Windows, -- компонент с `<>:"\|?*` или
управляющим символом, имя устройства (CON, PRN, AUX, NUL, COM1-9, LPT1-9, в
том числе с расширением), имя, оканчивающееся точкой или пробелом, -- не
извлекается, и об этом сообщается; точка повторной обработки (reparse
point) на пути отвергается. Данные и листинг выводятся байт в байт, как в
Linux.

Для vbkx.exe не нужны ни StarLet, ни CMake. С MinGW-w64, из корня дерева
исходных текстов:

```
$ x86_64-w64-mingw32-gcc -O2 -Ilib -o vbkx.exe tools/vbkx.c \
      lib/vbkfmt.c lib/vbkrd.c lib/vbklz4.c lib/vbkcrp.c -static -lshell32
$ make -f tools/Makefile.win
```

### C.9 Распаковщики последней надежды: vbkx-go, vbkx-rs, vbkx-pl

Ещё три распаковщика хранятся на тот день, когда всё остальное умерло:

| Программа | Исходный текст | Сборка |
|---|---|---|
| vbkx-go | `tools/go/main.go` | `go build -o vbkx-go main.go` (Go 1.19 или новее) |
| vbkx-rs | `tools/rust/src/main.rs` | `rustc -O -C strip=symbols -o vbkx-rs src/main.rs` (Rust 1.63 или новее) или `cargo build --release` |
| vbkx-pl | `tools/perl/vbkx.pl` | Собирать нечего: `perl vbkx.pl ...` (Perl 5.10 или новее, только модули `perl-base`) |

`make` в `tools/go` и `tools/rust` делает то же; сборка CMake собирает vbkx-go
и vbkx-rs, если найдены Go или Rust. Каждый -- один исходный файл,
использующий только стандартную библиотеку, нарочно простой, чтобы его
можно было прочесть и исправить по `format.md`; заголовок каждого
исходного текста -- его руководство.

**Формат**

```
vbkx-go l saveset [-k file]
vbkx-go x saveset [-C dir] [-k file]
vbkx-go t saveset [-k file]
vbkx-go selftest
```

(то же для `vbkx-rs` и `perl vbkx.pl`)

| Команда | Действие |
|---|---|
| `l` | Выводит файлы по записям FILE потока (каталог не нужен), время в UTC. |
| `x` | Извлекает все файлы в *dir* (по умолчанию -- текущий каталог). Существующий файл никогда не перезаписывается. |
| `t` | Читает весь saveset и проверяет контрольные суммы. |
| `selftest` | Проверяет SHA-256, HMAC-SHA256, PBKDF2 и ChaCha20 по векторам их стандартов. |

Листинг у всех трёх одинаков байт в байт:

```
2026-10-03 20:40:12         1234 -0644 tree/a.txt
2026-10-03 20:40:12            5 l0777 tree/link -> a.txt
2026-10-03 20:40:12            6 h0644 tree/hard link to tree/a.txt
```

Они восстанавливают данные (дыры остаются дырами), режимы с битами setuid,
setgid и sticky, времена изменения и доступа, каталоги, символические
ссылки, жёсткие ссылки и FIFO; не восстанавливают владельцев, ACL,
расширенные атрибуты, флаги chattr, файлы устройств и сокеты. Записи DATAZ
читаются собственным проверяющим декодером LZ4, зашифрованные saveset-ы --
с `-k keyfile`, иначе `VBACKUP_KEY_FILE`, иначе с паролем, запрашиваемым на
терминале без эха; каждый блок проверяется по тегу до расшифровки, а
подделанный блок восстанавливается по группе, как плохой. Они чинят один
плохой блок на группу, после потери продолжают со следующего исправного
блока, пропускают отсутствующий или обрезанный том, находят размер блока
перебором, если потерян первый блок тома 1, и называют каждый
повреждённый (`is incomplete`) или недостающий (`was not extracted`) файл.
Saveset `/PHYSICAL` выходит как файл образа устройства, saveset `/IMAGE` --
как дерево его файлов.

vbkx-pl использует Digest::SHA, если он установлен, -- только ради скорости;
без него собственный SHA-256 примерно в сто раз медленнее (открытие
зашифрованного saveset-а тогда занимает минуты). `VBKXPL_PURE=1` заставляет
использовать собственный код, даже если Digest::SHA есть. Скорость чтения --
несколько мегабайт в секунду.

Коды завершения всех трёх: 0 -- всё сделано; 1 -- что-то повреждено или не
сделано; 2 -- команду или saveset нельзя использовать.

## Приложение D Модули файловых менеджеров

### D.1 Общие сведения

Saveset открывается как папка в перечисленных ниже файловых менеджерах:
листинг, просмотр, копирование наружу, проверка. Все модули работают
только на чтение: в saveset никогда ничего не пишется. Листинг берётся из
каталога, поэтому saveset в сотни гигабайт открывается сразу, а файл
копируется наружу по своему месту в каталоге.

Файловый менеджер не может спросить пароль. Чтобы открыть зашифрованный
saveset, поместите пароль в файл ключа (`chmod 600`) и назовите этот файл в
переменной окружения `VBACKUP_KEY_FILE` до запуска файлового менеджера (в
Windows -- в системных настройках переменных окружения). Без неё saveset не
открывается; ничто не ждёт ответа на экране. Модули устанавливают
`VBACKUP_NOPROMPT=1` или передают vbkx ключ `-n`.

### D.2 Midnight Commander

| Элемент | Значение |
|---|---|
| Файлы | `plugins/mc/uvbk` (сценарий extfs), `plugins/mc/mc.ext.ini.vbackup` (раздел `mc.ext.ini`) |
| Работает поверх | `vbackup` (переменная `VBACKUP` может назвать другой образ) |
| Установка | `cmake --install` помещает `uvbk` в каталог extfs MC, а раздел -- в `mc.ext.ini`, если MC установлен, и убирает их при удалении. Вручную: скопируйте `share/vbackup/plugins/mc/uvbk` в `~/.local/share/mc/extfs.d` (или `/usr/lib/mc/extfs.d`), а раздел -- в `mc.ext.ini` перед `[Default]`. |
| Использование | Enter на файле `.bck`; F3 показывает полный листинг. |

Раздел:

```
[vbackup]
Shell=.bck
ShellIgnoreCase=true
Open=%cd %p/uvbk://
View=%view{ascii} vbackup %f /SAVE_SET /LIST /FULL
```

`uvbk list` выдаёт каталог строками `ls -l` (`vbackup ARCHIVE /LIST
/FORMAT=LS`); `uvbk copyout` извлекает один файл (`vbackup ARCHIVE TARGET
/EXTRACT=NAME`). Копирование внутрь, удаление и создание каталогов
отвергаются. Saveset из нескольких томов открывается только с локального
диска: внутри другой VFS (архив, FTP) MC передаёт сценарию временную копию
тома 1, и остальных томов рядом с ней нет.

### D.3 far2l и Far Manager 3

| Элемент | Значение |
|---|---|
| Файл | `plugins/far/vbackup.ini`, описание формата для модуля MultiArc |
| Работает поверх | vbkx (`vbkx.exe` в Windows, ищется по PATH) |
| Установка | far2l: дописывается в `~/.config/far2l/plugins/multiarc/custom.ini` (это делает установка). Far3: допишите его в `Plugins\MultiArc\Formats\custom.ini`. |
| Использование | Enter или Ctrl/PgDn на файле `.bck`; F5 копирует файлы наружу. |

Команды, которые запускает MultiArc:

```
List=vbkx l %%AQ -m -n
Extract=vbkx x %%AQ -f -n %%FSQ
ExtractWithoutPath=vbkx x %%AQ -f -j -n %%FSQ
Test=vbkx t %%AQ -n
```

Saveset распознаётся по первым четырём байтам `VBKB` (`ID=56 42 4B 42`) и по
расширению `bck`.

### D.4 Total Commander и Double Commander

| Элемент | Значение |
|---|---|
| Исходный текст | `plugins/wcx/vbkwcx.c`, модуль упаковщика WCX поверх ядра чтения |
| Файлы | `vbackup.wcx64` (Total Commander, 64 бита), `vbackup.wcx` (Total Commander, 32 бита), `vbackup.wcx` -- разделяемый объект -- для Double Commander в Linux |
| Сборка | `make -f plugins/wcx/Makefile linux win64 win32` (в `out/linux`, `out/win64`, `out/win32`); сборка CMake всегда собирает модуль для Linux (устанавливается в `share/vbackup/plugins/wcx`) и модули для Windows, если найден MinGW-w64 |
| Установка в TC | Откройте архив модуля (`make -f plugins/wcx/Makefile zip`, с `pluginst.inf`) в TC и подтвердите; или Configuration -> Options -> Packer -> Configure packer extension WCXs, расширение `bck`. |
| Установка в DC | Options -> Plugins -> Packer plugins (WCX) -> Add, расширение `bck`. |

Модуль строит листинг по каталогу (без каталога или с повреждённым
каталогом -- читает saveset целиком), копирует файл наружу по его месту в
каталоге, проверяя FILENO и CRC, читает записи DATA и DATAZ и дыры, чинит
то, что позволяют блоки XOR, и сообщает о файле, не извлечённом целиком
(E_BAD_DATA). Том, которого нет рядом с томом 1, запрашивается через
обратный вызов ChangeVol. Имя, ведущее за пределы целевого каталога (`..`,
ведущая `/`, обратная косая черта; в Windows также `c:`, `con`, `x?`), в
листинг не попадает. За пределы целевого каталога ничего не пишется.

Ограничения: зашифрованный saveset открывается только с `VBACKUP_KEY_FILE`
(без неё -- E_EOPEN, с неверным паролем -- E_BAD_ARCHIVE); владельцы, ACL,
расширенные атрибуты и флаги chattr не восстанавливаются; файлы устройств,
FIFO и сокеты показываются в листинге, но не создаются; символические
ссылки создаются в Linux и пропускаются в Windows; времена в листинге --
времена DOS (местные, с шагом две секунды), а извлечённый файл получает
свои времена полностью.
