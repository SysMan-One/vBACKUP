# VBACKUP

English: [README.md](README.md)

Утилита saveset-ов для Linux в стиле OpenVMS BACKUP: сохранить файлы в
saveset, восстановить их, получить листинг и сравнить -- одна команда,
квалификаторы BACKUP.

    $ vbackup /home/rrl /backup/rrl.bck /VERIFY
    $ vbackup /backup/rrl.bck /LIST
    $ vbackup /backup/rrl.bck /tmp/restore

Что даёт saveset:

- файлы с владельцами, правами, временами с точностью до наносекунды,
  расширенными атрибутами, POSIX ACL, capabilities, флагами chattr;
  жёсткие и символические ссылки, разреженные файлы, FIFO, устройства;
- контрольная сумма каждого блока и каждого файла: повреждение всегда
  обнаруживается;
- XOR-блоки (`/GROUP_SIZE`): один испорченный блок в группе
  восстанавливается, а после потери чтение подхватывает поток со
  следующего хорошего блока -- страдают только файлы, лежавшие в
  потерянных блоках;
- тома (`/VOLUME_SIZE=4G`), каждый из которых сам себя идентифицирует --
  на диске, через канал или прямо на другом узле
  (`vbackup /home host::/backup/home.bck`, как писали в DECnet);
- каталог в конце: `/LIST` и `/EXTRACT` работают мгновенно;
- инкрементные сохранения: `/RECORD` ведёт журнал, `/SINCE=BACKUP`
  сохраняет то, что изменилось с тех пор, а цепочка, восстановленная с
  `/INCREMENTAL`, возвращается без удалённых файлов;
- копирование с диска на диск со всем, что вернуло бы восстановление;
- сжатие (`/DATA_FORMAT=COMPRESSED`, LZ4 на всех ядрах), целое
  устройство блок за блоком (`/PHYSICAL`) или целая файловая система
  (`/IMAGE`);
- шифрование (`/ENCRYPT`, `/KEY_FILE`): ChaCha20 и HMAC-SHA256 на каждый
  блок, ключи через PBKDF2 -- имена файлов тоже скрыты, повреждение
  по-прежнему исправляется без пароля, намеренно изменённый блок
  распознаётся; криптографическая библиотека не используется, поэтому
  все перечисленные ниже читатели его читают;
- `vbkx` -- автономный распаковщик, собранный статически: листинг,
  извлечение и проверка saveset-а там, где VBACKUP не установлен
  (`vbackup /HELP VBKX`);
- saveset-ы OpenVMS BACKUP тоже читаются: листинг как у `BACKUP/LIST`,
  файлы восстанавливаются с именами Linux, тексты становятся текстами,
  плохие блоки чинятся по их XOR-группам -- в vbackup, vbkx, vbkx.exe,
  Midnight Commander; far2l, модуль WCX и распаковщики для гиков их не
  читают (`vbackup /HELP OPENVMS`, [doc/vmsbackup.md](doc/vmsbackup.md));
- никаких зависимостей, кроме libc, StarLet и HELP.

Формат описан в [doc/format.md](doc/format.md) (на английском);
устройство -- в [doc/DESIGN.md](doc/DESIGN.md).  Руководство
пользователя -- это библиотека справки: `vbackup /HELP`, исходные тексты
в [doc/vbackuplib_ru.md](doc/vbackuplib_ru.md) и
[doc/vbackuplib.md](doc/vbackuplib.md) (на английском).

Впервые со всем этим?  Простые руководства, задача за задачей, с
командами, которые можно скопировать: [Русский](doc/simple/vbackup-ru.md),
[English](doc/simple/vbackup-en.md), [Español](doc/simple/vbackup-es.md).

## Почему VBACKUP, а не tar, dar, borg или dd

Каждый из них хорош в том, для чего его сделали.  VBACKUP сделан ради
одного, что важнее скорости: чтобы сохранённое вернулось -- с
повреждённого диска, на машине, где ничего не установлено, спустя годы.

**Повреждение исправляется, а не только обнаруживается.**  У каждого
блока и каждого файла есть контрольная сумма, поэтому повреждение никогда
не проходит молча.  XOR-блок каждой группы (`/GROUP_SIZE`) восстанавливает
один испорченный блок группы, ни о чём не спрашивая; если потеряно
больше, чтение подхватывает поток со следующего хорошего блока, и
страдают только файлы, лежавшие в потерянных блоках, -- и они называются
по именам.  Сжатый tar нечитаем после первого же испорченного байта;
простой tar проверяет только заголовки, так что повреждённое содержимое
возвращается неверным, и никто этого не замечает.  dar исправляет
повреждения только с помощью файлов par2, сделанных рядом с ним; borg и
restic обнаруживают повреждение, а испорченный фрагмент
дедуплицированного репозитория портит все резервные копии, которые его
разделяют.

**Читается без VBACKUP.**  Формат -- открытая полная спецификация
([doc/format.md](doc/format.md), на английском), и помимо VBACKUP у него
есть четыре независимых читателя: `vbkx` (статический, на C, есть и
`vbkx.exe` для Windows) и `vbkx-go`, `vbkx-rs`, `vbkx-pl` -- каждый из
одного исходного файла и без зависимостей, кроме стандартной библиотеки
языка.  Аварийная система с компилятором C, или Go, или Rust, или только
с Perl прочитает saveset -- и зашифрованный тоже.

**Шифрование, за которое не платишь возможностью восстановления.**
ChaCha20 и HMAC-SHA256 на каждый блок, ключи через PBKDF2: контрольные
суммы и XOR-группы лежат поверх шифротекста, поэтому повреждённый
зашифрованный saveset восстанавливается без пароля, а намеренно
изменённый блок распознаётся и восстанавливается.  Криптографическая
библиотека не используется, поэтому все перечисленные выше читатели его
читают.

**Мгновенные листинг и извлечение.**  Каталог в конце saveset-а выдаёт
листинг сотен гигабайт сразу, а к отдельному файлу VBACKUP переходит по
его месту, записанному в каталоге, -- tar же должен прочитать всё, что
лежит перед ним.  Через канал или в повреждённом saveset-е без каталога
вместо этого читается поток.

**Один инструмент для файлов, томов и устройств.**  Файлы со всем, что
даёт им Linux (владельцы, времена с точностью до наносекунды, xattr,
ACL, capabilities, флаги chattr, жёсткие ссылки, разреженные файлы);
`/IMAGE` -- целая файловая система, воссозданная с её меткой и UUID;
`/PHYSICAL` -- устройство блок за блоком, с пропуском нулевых участков, с
теми же контрольными суммами, восстановлением, сжатием и шифрованием,
которых нет у образов dd, partclone и Clonezilla.  Тома любого размера,
каждый сам себя идентифицирует; инкрементные цепочки с журналом,
восстановление, которое удаляет то, что было удалено; копирование с
диска на диск; saveset-ы через ssh.

**Мост с OpenVMS.**  Saveset, записанный OpenVMS BACKUP, -- со старого
диска, с ленты, скопированной в файл, из архива VAX или Alpha --
читается в Linux: `vbackup USERS.BCK /LIST /FULL` печатает то же, что
`BACKUP/LIST/FULL`, байт в байт; восстановление даёт файлам имена Linux
(`[SMITH]LOGIN.COM;3` -- это `SMITH/LOGIN.COM`, младшие версии
сохраняют `;n`), делает тексты текстами и чинит плохие блоки по
XOR-группам, как это сделал бы BACKUP.  `vbkx` и `vbkx.exe` его тоже
читают.  Никто из остальных этого не умеет.

**Команды OpenVMS BACKUP.**  `/SAVE_SET`, `/SINCE=BACKUP`, `/RECORD`,
`/INCREMENTAL`, `/IMAGE`, `/PHYSICAL`, `/VERIFY`, `/LIST`, `/SELECT`,
`/EXCLUDE` -- со справкой HELP, сообщениями в форме VMS и справочным
руководством в манере DEC ([doc/ref](doc/ref/vbackup_ref_ru.md)).

**Расписание и ротация оставлены пакетной очереди.**  BATCH (подсистема
пакетных заданий) запускает сохранение каждую ночь так, как это делается
в OpenVMS, -- задание, которое само ставит себя снова в очередь на
следующий день, ведёт свой журнал и остаётся в очереди, если завершилось
неудачно (`vbackup /HELP SCHEDULING`).

**В файловых менеджерах.**  Midnight Commander, far2l и Far, Total и
Double Commander открывают saveset как папку (только для чтения).

| | VBACKUP | tar (.gz) | dar | borg / restic | dd / partclone |
|---|---|---|---|---|---|
| Контрольная сумма каждого блока и файла | да | только заголовки | да | да | нет |
| Сам исправляет испорченный блок | да (XOR-группа) | нет | с par2 | нет | нет |
| Распространение повреждения | только потерянные блоки | до конца (.gz) | срез | общие фрагменты | - |
| Читатели без самого инструмента | 4, без зависимостей | много | нет | нет | много |
| Шифрование, восстановление без ключа | да, без библиотеки | нет | libgcrypt | да, нет | нет |
| Листинг большой резервной копии | каталог, мгновенно | читает всё | каталог | индекс | - |
| Тома | да | многотомный, неудобно | срезы | - | split |
| Целое устройство / файловая система | `/PHYSICAL`, `/IMAGE` | нет | нет | нет | да |
| Читает saveset-ы OpenVMS BACKUP | да, с починкой | нет | нет | нет | нет |
| Дедупликация | **нет** | нет | нет | **да** | нет |
| Удалённый репозиторий | канал через ssh | канал | канал | **да** | канал |

**В чём другие лучше.**  borg и restic дедуплицируют -- сотня ежедневных
резервных копий большого дерева стоит немногим больше одной -- и ведут
удалённый репозиторий; VBACKUP делает самодостаточные saveset-ы, по
одному на сохранение, для носителей, которые кладут на полку.  tar есть
везде, и его читает любой инструмент.  VBACKUP молод: его формат
зафиксирован и проверен собственными тестами на повреждения, но у него
нет десятилетий эксплуатации, которые есть у других.

## Для гиков: vbkx-go, vbkx-rs, vbkx-pl

Ещё два распаковщика последней надежды -- на тот день, когда всё
остальное мертво: [tools/go/main.go](tools/go/main.go) и
[tools/rust/src/main.rs](tools/rust/src/main.rs).  По одному файлу,
только стандартная библиотека, намеренно просто, чтобы их можно было
прочитать и исправить по [doc/format.md](doc/format.md).  Они за один
проход выдают листинг (`l`, времена в UTC), извлекают (`x`) и проверяют
(`t`) saveset, восстанавливают один испорченный блок на группу,
подхватывают поток после потери, находят размер блока перебором, если
том 1 потерял свой первый блок, и называют каждый повреждённый или
недостающий файл.  Они читают и сжатые saveset-ы (DATAZ, блочный формат
LZ4, каждый со своим проверенным декодером), и зашифрованные (`-k
keyfile`, иначе `VBACKUP_KEY_FILE`, иначе пароль запрашивается с
терминала): каждый блок проверяется по его TAG до расшифровки,
подделанный блок восстанавливается из своей группы, как испорченный;
то, чего не даёт язык, расписано в каждом файле, а `selftest` проверяет
примитивы по тестовым векторам их стандартов.  Начало каждого
исходного файла -- его руководство.

    $ go build -o vbkx-go main.go                         # in tools/go
    $ rustc -O -C strip=symbols -o vbkx-rs src/main.rs    # in tools/rust

`make` в любом из этих каталогов делает то же самое; для Rust работает и
`cargo build --release`.  Сборка CMake собирает их, если найдены Go или
Rust.

И третий, которому вообще ничего не нужно собирать:
[tools/perl/vbkx.pl](tools/perl/vbkx.pl), `vbkx-pl`.  Ему нужен только
Perl, который есть в каждой системе Debian и Ubuntu (пакет `perl-base`:
strict, warnings, Fcntl, POSIX); он делает то же, что и два предыдущих, с
тем же листингом, и он медленный (несколько МБ в секунду) и надёжный.
Для зашифрованного saveset-а он использует Digest::SHA, если тот есть, и
собственную реализацию SHA-256, если нет.  Скопируйте его рядом с
saveset-ом:

    $ perl vbkx.pl l /mnt/usb/home.bck
    $ perl vbkx.pl x /mnt/usb/home.bck -C /tmp/restore

Saveset, сделанный с `/PHYSICAL`, любой распаковщик выдаёт как файл
образа устройства; сделанный с `/IMAGE` -- как обычное дерево файлов
тома.

## vbkx в Windows

`vbkx.exe` читает saveset-ы в Windows, с теми же командами, что и
`vbkx`.  Ему не нужны ни StarLet, ни CMake; с MinGW-w64, из корня дерева
исходных текстов:

    $ x86_64-w64-mingw32-gcc -O2 -Ilib -o vbkx.exe tools/vbkx.c \
          lib/vbkfmt.c lib/vbkrd.c lib/vbklz4.c lib/vbkcrp.c lib/vbkvms.c -static -lshell32
    $ make -f tools/Makefile.win                     # the same
    $ cmake -S . -B build-win -DCMAKE_TOOLCHAIN_FILE=cmake/mingw-w64.cmake

В самой Windows ту же строку принимает gcc из MinGW-w64 или MSYS2.  Он
возвращает данные, времена, файлы только для чтения, каталоги и жёсткие
ссылки; символические ссылки -- там, где Windows их разрешает (режим
разработчика).  Имя, которое Windows не может хранить (`a:b`, `x?`,
`con.txt`, ...), не извлекается, и об этом сообщается.  `test/win.sh`
запускает его под wine.

## Файловые менеджеры

Saveset открывается как папка в перечисленных ниже файловых менеджерах:
листинг, просмотр, копирование наружу, проверка.  Только для чтения --
в saveset никогда ничего не записывается.  Листинг берётся из каталога,
поэтому saveset в сотни гигабайт открывается сразу, а файл копируется
наружу по его месту в каталоге.

- **Midnight Commander** -- [plugins/mc/uvbk](plugins/mc/uvbk), скрипт
  extfs поверх `vbackup`.  `cmake --install` кладёт его в extfs MC, а его
  секцию -- в `mc.ext.ini`, если MC установлен (и убирает их обратно при
  удалении); после этого Enter на файле `.bck` или `.sav` -- или на
  saveset-е с любым именем: установка добавляет магию VBACKUP в
  `/etc/magic`, и MC узнаёт его по содержимому.
- **far2l и Far3** -- [plugins/far/vbackup.ini](plugins/far/vbackup.ini),
  описание формата для MultiArc поверх `vbkx` (`vbkx.exe` в Windows).
  Установка дописывает его в `custom.ini` MultiArc из far2l.
- **Total Commander и Double Commander** -- [plugins/wcx/vbkwcx.c](plugins/wcx/vbkwcx.c),
  WCX-плагин упаковщика поверх читающего ядра: `vbackup.wcx64` и
  `vbackup.wcx` для 64- и 32-битного Total Commander, `vbackup.wcx`
  (разделяемый объект) для Double Commander в Linux.  Он проверяет CRC
  каждого файла, исправляет то, что позволяют XOR-блоки, называет то, что
  они не позволяют, запрашивает том, которого нет рядом с томом 1, и не
  даёт подделанному saveset-у писать за пределы целевого каталога.  Установка
  в TC: откройте zip с плагином и
  [pluginst.inf](plugins/wcx/pluginst.inf) (`make -f plugins/wcx/Makefile zip`)
  или Configuration -> Options -> Packer -> Configure packer extension
  WCXs, расширение `bck`.  В DC: Options -> Plugins -> Packer plugins
  (WCX) -> Add, расширение `bck`.  Начало исходного файла -- его
  руководство.

      $ make -f plugins/wcx/Makefile linux win64 win32   # out/linux, out/win64, out/win32

  Сборка CMake всегда собирает плагин для Linux (устанавливается в
  `share/vbackup/plugins/wcx`), а плагины для Windows -- если найден
  MinGW-w64; `test/wcx.sh` проверяет их по `vbkx` -- нативно и под wine.

## Сборка

Требуется StarLet 1.6 или новее; HELP 1.0 (необязательно) -- для
`/HELP` и библиотек справки.

    $ cmake -S . -B build
    $ cmake --build build
    $ (cd build && ctest)
    $ cmake --install build

`make kit` в дереве сборки делает `vbackup-<ident>.tar.gz` -- в дереве
git через git archive от HEAD, так что в него попадает только
закоммиченное.

Тесты говорят на TAP (Test Anything Protocol), если задано `TAP=1`, --
для prove, Jenkins, GitLab и им подобных; без него они печатают только
сбои:

    $ TAP=1 build/test/units /tmp/u.d
    $ prove -e "env TAP=1 VBACKUP=build/vbackup VBKX=build/vbkx SCRATCH=/var/tmp/s sh" test/smoke.sh
